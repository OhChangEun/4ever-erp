# Codex 와 Claude 역할 교대 실험

- 기간: 2026-11-10 22:30 ~ 23:55. 대상 저장소 4ever-erp(PR #85~#102 와 AppError 카드).
- 사용자 지시: 구현은 Codex, Claude 는 Codex 가 하던 리뷰를 맡고, 둘을 비교한다. 비교 항목은 AI 가 정한다. 도중에 "가장 비싼 Codex 설정으로 남은 토큰을 최대한 빨리 써라"가 더해졌다. Codex 사용량 한도(23:50경, 다음 사용 가능 01:58)에서 끝났다.

## 1. 결론

1. 구현 품질은 비슷했고, 속도는 Codex 가 4배 빨랐다. 같은 과제 맞대결에서 둘 다 게이트를 한 번에 넘었고 규칙 위반 0, 보고의 틀린 주장 0 이었다. 리뷰에서 걸린 정합성 문제(P2)는 Codex 쪽에만 하나 있었다(영어 단복수).
2. 리뷰어로는 Claude 가 더 많이, 더 정확히 잡았다. 같은 diff, 같은 지시문에서 Codex 리뷰는 P2 1건을 48초에 잡았고, Claude 리뷰는 그 P2 와 P3 7건을 3~5분에 잡았다. 7건 모두 재현해 보니 진짜였다. 교대 전 Codex 리뷰는 10장 연속 지적 0 이었다(지시문이 달라 비교는 참고).
3. Codex 의 강점은 서버 계약 확인이었다. 브리프에 백엔드 사본 경로를 주자 카드마다 DTO 와 컨트롤러를 열어 보고, 화면이 서버와 어긋나는 곳을 찾아냈다. 가짜 `requesterId` 전송, 주문 날짜 파라미터 이름(`start/end` vs `startDate/endDate`), 견적 상태 `APPROVAL` 검증이 그 예다. 모두 우선순위 1(화면과 서버 일치)이다. 같이 찾은 프로필 경로의 빠진 `/{internelUserId}` 는 사실이지만, 그 경로를 부르는 화면이 없어 실제 영향은 없었다(2026-11-11 확인, PR #104 에서 삭제).
4. Codex 는 브리프를 글자 그대로 따른다. Codex 쪽 지적 6건 중 2건은 브리프 문장이 원인이었다. 하나는 "가운뎃점 금지"를 기존 화면 글자에도 적용한 것이고, 다른 하나는 "서버 메시지는 온 그대로"를 서버 메시지를 새로 붙이라는 뜻으로 읽은 것이다. Codex 에게 맡길 때는 브리프의 정확도가 결과를 정한다.
5. 운영 실수는 모두 조율자(Claude) 쪽에서 났다. worktree 삭제(원인 미확정), 명령 연쇄 꼬임 두 번, zsh 단어 분리 두 번이 있었다. 결과물은 잃지 않았다. 구현자 비교 지표에는 넣지 않았다.
6. 이 프로젝트에 권하는 방식: 범위가 분명한 카드는 Codex 가 구현하고, 리뷰는 Claude 가 우선순위 표 지시문으로 한다. Codex 리뷰는 머지 직전 빠른 1차 확인으로 쓴다. 브리프에는 근거 경로(백엔드 사본, 계약)와 "바꾸면 안 되는 것"을 문장으로 박아 둔다.

## 6. 사고 기록

1. worktree 삭제(22:59): 맞대결 두 worktree 와 브랜치가 커밋 전에 지워졌다. 이 세션의 에이전트와 Codex 기록에는 삭제 명령이 없다. 같은 시각 다른 세션이 Orca 로 worktree 를 만들었다(원인 확정 못 함). Codex 리뷰 기록에 남은 `git diff` 출력으로 두 구현을 되살렸고, 테스트 수가 원래와 같았다. 이후 실험 결과는 바로 로컬 커밋했다.
2. 명령 연쇄 꼬임 두 번: `git add -N` 표시로 stash 가 실패해 rebase 가 건너뛰어졌고, commitlint(본문 100자)에 막힌 코드가 문서 커밋에 섞인 채 PR #98 이 올라갔다(닫고 #99). 묶음 PR 때는 `git apply --3way` 가 파일을 미리 스테이징해 문서가 코드 커밋에 섞였다(push 전에 다시 나눔). force-push 는 하지 않았다.
3. zsh 단어 분리 두 번: 변수에 담은 명령과 파일 목록이 나뉘지 않아 게이트가 127 로 끝나고 커밋 순서가 뒤집혔다. 둘 다 결과를 다시 확인해 바로잡았다.
4. 마무리는 이후 단계마다 실패하면 멈추는 스크립트로 했다.

## 8. 교대 뒤 이어진 기록 (2026-11-11, Claude 구현 복귀)

Codex 사용량이 끝나 구현은 Claude(erp-dev 에이전트)로 돌아갔고, 리뷰는 작성자를 가린 새 Claude 에이전트가 같은 우선순위 표 지시문으로 했다. 카드 7장(PR #104~#109)에서 리뷰어가 낸 지적은 P1 1, P2 7, P3 약 30이었다. P1 은 메인 세션의 지시("게이트웨이 DTO 이름으로 맞춰라")가 원인이었다. 근거로 든 DTO 는 참조되지 않는 죽은 코드였고, git 이력의 실서버 테스트 커밋(2e17263)과 반대였다. 리뷰어가 git 이력까지 뒤져 잡았다. 1절 2번(리뷰는 Claude 가 더 많이, 더 정확히 잡는다)을 받치는 사례다. 백엔드 사본은 게이트웨이뿐이라, Map 이나 Object 로 넘기는 경로는 DTO 와 예시를 근거로 확정하지 않는다.
