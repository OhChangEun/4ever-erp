# Codex 와 Claude 역할 교대 실험

- 시작: 2026-11-10. 사용자 지시: 구현은 Codex, Claude 는 Codex 가 하던 리뷰를 맡고 둘을 비교한다. 비교 항목은 AI 가 정한다.
- 대상 저장소: 4ever-erp. 루프는 같다(카드, 브리프, 구현, 리뷰, 게이트, 머지).

## 1. 무엇을 비교하나, 왜

이 프로젝트 우선순위(정합성 > 실패 숨기지 않기 > 성능 > 유지보수)를 그대로 잣대로 쓴다. "코드를 잘 짜나"를 한 줄 점수로 만들지 않고, 사람이 diff 를 읽을 때 드는 비용과 위험을 나눠 잰다.

## 2. 실험 설계

1. 같은 과제 맞대결 1건: "@everp/ui 한국어 기본 문구"를 같은 기준 커밋, 같은 브리프로 Codex(worktree A)와 Claude erp-dev 에이전트(worktree B)가 따로 구현한다. 서로의 결과를 보지 않는다. 두 diff 를 Claude 와 Codex 가 각각 리뷰한다(M11). 객관 지표(M1, M3, M5, M10)를 먼저 보고, 나은 쪽을 머지한다.
2. Codex 단독 카드: 이후 카드는 Codex 가 구현하고 Claude 가 리뷰한다. 같은 종류의 Claude 카드(i18n 6~11, 결함 카드 4개)와 같은 지표로 비교한다. 과제가 달라 이 비교는 참고다. 맞대결이 주 근거다.
3. 편향 막기: Claude 가 Claude 결과를 리뷰하는 자기 편향이 있어 M11 은 교차로 하고, 판정은 재현된 지적만 센다.
