# 시각화 6: 공급망 흐름 Sankey(구매요청에서 출하까지)

- 출처: 계획 17-1 "구매와 영업: 공급망 흐름 Sankey: 구매요청 → 발주 → 입고 → 재고 → 출하", 17-2 규칙
- 우선순위: 1(대시보드에 올 때마다 새로 받는다, 알 수 없는 흐름을 그럴듯하게 그리지 않는다), 2(반려, 미입고처럼 새는 금액을 숨기지 않는다), 3(Recharts 는 동적으로)
- 브랜치: feat/시각화\_6\_공급망\_Sankey
- 크기: 반나절

## 현상

구매, 재고, 영업, 생산이 각자 화면에 있다. 이번 달 구매요청 금액 중 얼마가 발주로 가고, 얼마가 반려됐고, 입고된 것이 생산과 출하로 얼마씩 나갔는지 한 장으로 볼 곳이 없다.

## 완료 기준

1. 계약에 `GET /dashboard/supply-flow`(기간, 노드 목록 `{ id, name, kind: flow | drop }`, 흐름 목록 `{ source, target, value }`, 금액은 원). 목은 openapi-msw.
2. 대시보드 아래에 "이번 달 자재 흐름(금액)" 카드: Recharts `Sankey`(`next/dynamic`). 노드 옆에 이름과 금액을 직접 라벨로. 새는 흐름(kind drop: 반려, 입고 대기)은 회색, 본 흐름은 브랜드 색.
3. 요약 문장(단계마다 금액, 새는 금액 합계와 비율)을 설명으로 잇고, "표로 보기"가 흐름 표(출발, 도착, 금액)를 연다.
4. 응답 검사: 모르는 노드를 가리키는 흐름은 빼고 "알 수 없는 흐름 N건은 뺐습니다"를 보인다. 순환이 있으면 차트를 그리지 않고 표만 보인다(Recharts Sankey 는 순환을 못 그린다).
5. 권한: 사내 운영 역할(ALL_ADMIN, 구매, 영업, 재고, 생산)만. 카드와 BFF 인가 표 `API_RULES` 둘 다(시각화 4 의 교훈). 재무, 인사, 고객사, 공급사는 카드도 API 도 없다.
6. 쿼리 키 `dashboardKeys.supplyFlow()`, staleTime 0. 다른 도메인 mutation 에서 대시보드 키를 무효화하지 않는 대신 대시보드에 올 때마다 다시 받는다.
7. 대시보드 첫 로드 JS 예산 안.

## 결정 (AI 가 정함)

1. 단위는 금액(원). 단계마다 건수와 수량은 단위가 달라 한 흐름으로 못 잇는다. 원가 기준이라는 건 카드 제목의 "(금액)"과 요약에 적는다.
2. 그래프 모양은 서버가 정한다(노드와 흐름 목록). 화면은 단계 순서를 하드코딩하지 않는다. 서버가 단계를 바꿔도 그대로 그린다.
3. 무효화 대신 staleTime 0. 대시보드는 여러 도메인을 모은 화면이라 각 도메인 mutation 표에 대시보드 키를 넣으면 "다른 도메인은 건드리지 않는다"는 규칙을 어긴다.
