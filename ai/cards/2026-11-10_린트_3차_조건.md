# 린트 3차: 필요 없는 조건(no-unnecessary-condition)

- 출처: 린트 2차 결정 1
- 우선순위: 2(실패를 숨기던 결함 2개), 1(서버 값 가드는 검증이 있는 곳에서만 지운다), 4
- 브랜치: refac/린트\_3차\_조건

## 완료 기준

1. 77개를 세 가지로 나눠 처리한다.
   - 화면 안의 값이라 확실히 필요 없는 조건: 지운다.
   - 타입이 거짓말하는 곳(`Record<string, X>` 조회, 배열 인덱스, 정리 함수가 바꾸는 변수): 타입을 정직하게(`Partial`, `at()`, 함수로 읽기) 고쳐 가드를 남긴다.
   - 서버 응답 가드: 응답을 zod 로 검증하는 도메인(영업, 구매, 생산)에서만 지운다. 검증이 없는 도메인은 남긴다.
2. 동작이 바뀌는 곳은 테스트를 더한다.

## 결정 (AI 가 정함)

1. 검증 없는 도메인(대시보드, 재무, 인사, 재고, 창고)의 서버 값 가드 36개는 남기고 규칙은 warn 그대로. 타입은 null 이 아니라고 하지만 서버가 그렇게 주는지 확인된 적이 없다(우선순위 1 이 린트 0 보다 앞). 그 도메인 읽기에 zod 를 붙이는 카드에서 지운다.
2. `Spacing` 의 `size` 를 숫자 전체에서 표에 있는 10개로 좁혔다(리뷰 P2: 가드를 지우자 `size={5}` 가 화면을 깨뜨렸다). 쓰는 곳은 `size={12}` 하나.

## 결과

1. 경고 77 → 36(남은 것은 결정 1 의 서버 값 가드).
2. 찾아서 고친 결함 둘:
   - 발주서 상세 모달: `if (!order) return null` 이 로딩, 오류 검사보다 앞이라 불러오는 중에도 실패해도 빈 화면이었다. 순서를 바꾸고 테스트 2개(고치기 전 코드에서 둘 다 실패 확인).
   - 원자재 등록 모달: 같은 조건(`errorDialog.isOpen`)을 두 번 검사해 창고 조회가 실패해도 "자재 정보" 오류 문구가 떴다. 어느 쪽 실패인지에 따라 문구를 고른다.
3. 재무 전표 목록의 죽은 분기(탭은 매출, 매입 둘뿐인데 셋째 분기) 정리, 상태 색과 알림 출처, 데모 계정 조회를 `Partial` 로.
4. 확인: verify(앱 401), e2e 71 통과 + 1 흔들림(로그아웃 쿠키 테스트, 다시 9번 돌려 모두 통과, API 를 직접 불러 이번 변경과 무관), 리뷰 2회(P2 1 고침).
