# React Compiler: 켜고 재 보고 끈다

- 출처: 계획 16-1 "React Compiler(린트 0 이 되면 reactCompiler: true, 켜기 전후 커밋 수 비교)"
- 우선순위: 3
- 브랜치: perf/React_Compiler
- 크기: 반나절

## 현상

React 훅 린트 억제가 0 이 되어(2026-11-10) 컴파일러를 켤 전제가 갖춰졌다. 켜면 얼마나 좋아지는지는 재 보지 않았다.

## 완료 기준

1. 같은 조작(기간 탭 4번, 드롭다운 열고 닫기 3번, 검색어 8자, 탭 전환 2번)을 운영 빌드에서 CPU 4배 감속으로 하고, JS 실행 시간(CDP ScriptDuration)과 React 커밋 수를 3번 재 중앙값을 낸다(`perf/compiler.spec.ts`).
2. 컴파일러를 켠 빌드와 끈 빌드를 같은 기계에서 비교한다. 첫 로드 JS 는 번들 예산 검사로.
3. 숫자로 켤지 정한다.

## 결정 (AI 가 정함)

1. 끈다. 결과 표 참고. 첫 로드 JS 가 라우트마다 +8~22KB(11개 라우트가 예산 +5KB 를 넘음) 늘고, 얻는 것은 조작 중 JS 6ms(8%)와 커밋 1회다. 목록이 페이지당 10행이라 리렌더 비용이 원래 작다.
2. 측정 스크립트는 남긴다. 목록이 커지거나(가상화, 전체 보기) React 버전이 바뀌면 다시 잰다.

## 결과

| 항목(3번 중앙값)              |      끔 |               켬 |      차이 |
| ----------------------------- | ------: | ---------------: | --------: |
| 조작 중 JS 실행 시간(CPU 4배) |    78ms |             72ms | -6ms(-8%) |
| React 커밋 수                 |      51 |               50 |        -1 |
| 첫 로드 JS(gzip), 구매        | 277.2KB |          296.9KB |   +19.7KB |
| 첫 로드 JS(gzip), 대시보드    | 244.2KB |          252.7KB |    +8.4KB |
| 첫 로드 JS(gzip), 인사        | 263.5KB |          285.4KB |   +21.9KB |
| 빌드 결과의 메모이제이션 캐시 |       0 | 733곳(청크 36개) |           |

1. 컴파일러가 실제로 적용됐는지는 빌드 청크의 `react.memo_cache_sentinel` 수로 확인했다.
2. 켠 상태는 커밋하지 않았다. 남긴 것은 측정 스크립트와 이 카드, ARCHITECTURE 9절(SKIP) 한 줄.
