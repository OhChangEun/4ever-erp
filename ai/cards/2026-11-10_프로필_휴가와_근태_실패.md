# 프로필 휴가 신청 실패와 근태 조회 실패

## 원인과 수정

- 휴가 신청은 요청 직후 모달을 닫고 입력을 초기화했다. 닫기와 초기화를 mutation onSuccess로 옮겨 실패 시 모달과 입력을 보존한다. 기존 toast.error와 errorMessageOf를 유지하고 pending 버튼 비활성화와 제출 가드를 적용했다.
- 오늘 근태와 최근 근태는 query 오류를 렌더링하지 않았다. 각각 TableStatusBox로 오류를 표시하며 실패 시 기존 데이터나 빈 기록 안내 대신 오류를 우선한다. 로딩 표시는 유지했다. 새 문구는 profile ko/en에 함께 추가했다.

## 근거

- 팀 백엔드 게이트웨이 HrmController와 LeaveRequestDto를 신뢰했다. 휴가 유형 ANNUAL/SICK과 YYYY-MM-DD 요청 형식을 유지한다. MSW auth.handlers.ts와 OpenAPI도 확인했다.
- ProfileController의 두 근태 조회는 Object 프록시이므로 값 계약을 확정할 수 없다. 기존 영문 코드와 한국어 상태 호환 처리를 유지하며 서버 동작을 새로 가정하지 않았다.

## 검증

- profile.failures.test.tsx 4개를 먼저 추가했다. 수정 전 입력 소실, 응답 전 모달 닫힘, 각 조회의 오류 표시 누락으로 모두 실패했다. 수정 후 모두 통과한다.
- 실패 시 입력 보존과 오류, 성공 후 닫기와 초기화, 대기 중 중복 제출 방지, 요청 본문 형식, 두 조회 실패를 검증한다.
- pnpm exec tsc --noEmit -p . 통과.
- pnpm exec eslint . 오류 0, 경고 0.
- pnpm exec vitest run 93개 파일, 575개 테스트 통과.
