# 타입 3차: 드롭다운 옵션 응답(DTO)과 화면 옵션 나누기

- 출처: 계획 7절 KeyValueItem 판정 3번, 블록 4 타입
- 우선순위: 4 유지보수성(서버 응답 모양이 바뀌어도 UI 컴포넌트 타입이 같이 흔들리지 않게)
- 브랜치: refac/타입_3차_옵션_DTO
- 크기: 한두 시간

## 현상

1. 드롭다운 옵션 API 22개(인사 8, 생산 9, 구매 7 중 옵션)가 화면 옵션 타입 `KeyValueItem` 을 응답 타입으로 그대로 쓴다. 서버가 필드 이름을 바꾸면 Dropdown 을 쓰는 화면 전체가 같이 바뀐다.
2. 변환하는 곳이 없어 응답에 딸려 온 필드가 화면 옵션까지 그대로 간다.

## 완료 기준

1. API 층은 `OptionResponse`(`src/app/types/api.ts`), 화면 층은 `KeyValueItem`. 바꾸는 곳은 `toKeyValueItems` 한 곳(테스트).
2. `useDropdown` 과 옵션을 직접 조회하는 4곳은 useQuery `select` 로 바꾼다. 캐시에는 응답 그대로, 화면에는 변환 결과.
3. 테스트, 빌드, e2e 통과. 새 경고 없음.

## 결정

1. 이름 바꾸기(`key`/`value` 를 `value`/`label` 로)는 하지 않는다. 계획 7절 1번대로 얻는 것이 이름뿐이다.
2. Role 유니온과 사용자 타입 위치 옮기기는 인증 블록(계획 8절 3번, 8번)에서 한다.

## 결과

1. `OptionResponse`, `optionListSchema`(영업, 구매, 생산 zod), `toKeyValueItems`(`src/lib/api/options.ts`).
2. 옵션 API 22개의 반환 타입을 `OptionResponse[]` 로. `useDropdown` 과 인사 화면 4곳(근태 상태, 교육 분류, 교육 프로그램, 프로그램 상태)이 select 로 바꾼다.
3. `KeyValueItem` 참조는 화면 쪽만 남았다(49).
4. 단위 181 통과(+1), 빌드 통과, e2e 38 통과. ESLint 경고 488 → 484.
