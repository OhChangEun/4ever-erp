### 왜 도메인마다 따로인가

- [사실] 처음엔 루트 레이아웃 한 곳이었다(161284d1, 2025-10-13). 22bf1125(2026-02-11)이 루트에서 빼고 도메인 레이아웃으로 나눴다. 일부러 한 것이다. 같은 커밋의 `docs/performance-refactor.md`(74298e66 에서 추적 제거)에 이유가 있다: 개발 모드의 라우트 이동 컴파일, 루트의 전역 결합, 첫 로드 번들. 캐시나 보안 때문이라는 말은 없다.
- [사실] 결정 기록에는 "나눈다"는 행이 없다. 사이드바만 2026-11-12 "카드 알림 UI 연결" 행으로 정했고, 2026-11-24 두 행이 나뉜 것을 전제로 적었다.
- [추론] 지금은 (private) 레이아웃이 사이드바용 클라이언트를 이미 만들어(`layout.tsx:22`) 첫 로드 근거는 거의 남지 않는다. 컴파일 근거는 측정 기록이 없다.

### 로그인과 캐시가 새는 길

1. [사실] 데모 로그아웃은 전체 새로고침이 아니다. `SidebarProfile.tsx:56` → `logout.ts:46` → `router.replace('/login')`. 로그인도 `router.replace`(`login/page.tsx:117`). JS 메모리가 남는다. 캐시를 비우는 코드(`queryClient.clear`)는 0곳이다. OIDC 로그아웃과 API 401 은 `location.assign` 이라 다 사라진다.
2. [사실] 쿼리 키에 사용자가 없다. 통계 네 곳은 role 만 있고 목록은 조건만 있다. 같은 키로 다른 사용자의 값이 나올 수 있다.
3. [사실+추론] 그래서 놓는 자리가 보안을 정한다.
   - `(private)/layout.tsx` 의 useState: `/login` 으로 가면 레이아웃이 내려가 같이 사라진다. `cacheComponents` 가 꺼져 있고(`next.config.ts`) 그때 Next 는 이전 화면을 숨겨 두지 않는다(`bfcache-state-manager.js:13`, 문서 `cacheComponents.md` 46). 새지 않는다(추론, e2e 로 확인할 것). `cacheComponents` 를 켜는 날 깨진다.
   - 루트 레이아웃이나 모듈 변수: 샌다. ADMIN 로그아웃 → 30초 안에 공급사 로그인이면 앞사람 목록이 요청 없이 나온다. Next 문서가 권하는 모양(`dist/docs/.../tanstack-query.md:28` 의 모듈 변수 `browserQueryClient`)이 이것이라 그대로 옮기면 안 된다.

### 목록이 두 번 나가는 이유

[추론, 코드로 설명이 끝난다. 쿼리 문자열로 확인할 것] 마운트 뒤 기본 선택이 바뀌어 키가 달라진다. `SearchBar` 는 자기 state 를 ''로 시작하고(`SearchBar.tsx`) `Dropdown` 의 effect 가 첫 항목을 골라 부모에 알린다(`Dropdown.tsx:114-118`). 부모의 처음 값이 첫 항목과 다르면 두 번이다. staleTime 과 StrictMode 와는 관계없다.

| 목록                                                                      | 처음 값                                  | effect 가 바꾸는 값         | 예상 |
| ------------------------------------------------------------------------- | ---------------------------------------- | --------------------------- | ---- |
| 재고 `InventoryList.tsx:35`                                               | `warehouse`                              | `WAREHOUSE_NAME`            | 2번  |
| 구매 요청, 발주(`PurchaseRequestListTab.tsx`, `PurchaseOrderListTab.tsx`) | ''                                       | 서버 검색 타입의 첫 값      | 2번  |
| 생산 MES(`MesTab.tsx:52, 275`), MRP 순소요(`OrdersTab.tsx:54, 237`)       | ''                                       | 서버 견적 옵션의 첫 값(ALL) | 2번  |
| 영업 3개                                                                  | 첫 항목과 같다(`constant.ts:18, 25, 32`) | 안 바뀜                     | 1번  |
| 안전재고, 전표                                                            | `ALL` 이 이미 있다                       | 안 바뀜                     | 1번  |

영업이 한 번이면 이 설명이 맞고, 영업도 두 번이면 틀렸다. 재고는 첫 요청에 서버에 없는 값 `type=warehouse` 도 보낸다.
