# 모노레포 2: 공통 컴포넌트를 packages/ui 로

- 출처: 계획 16-1 "packages/ui(공통 컴포넌트 30개)", 결정 기록 "모노레포"
- 우선순위: 4
- 브랜치: refac/모노레포_2_ui
- 크기: 반나절

## 현상

공통 컴포넌트가 앱 폴더(`src/app/components/common`)에 있어 앱 코드(도메인 타입, AppError, 훅)를 마음대로 가져올 수 있다. 그래서 앱 밖에서(Storybook, 다른 앱) 쓸 수 없다.

## 완료 기준

1. 앱에 묶이지 않은 컴포넌트 25개와 `useCloseOnEscape`, `KeyValueItem` 을 `packages/ui`(`@everp/ui`)로 옮긴다. 앱 모델에 묶인 것(`TableStatusBox`, `StatSection`, `StatusLabel`, `TabNavigation`, `SubNavigation`)과 날짜 유틸이 필요한 달력 3개, 모달과 토스트 Provider 는 다음 단계.
2. 앱의 import 를 변환 스크립트로 `@everp/ui` 이름 있는 import 로 바꾼다.
3. 패키지는 TS 소스를 그대로 내보내고(`exports: ./src/index.ts`) Next 가 변환한다(`transpilePackages`). `sideEffects: false`.
4. 패키지가 앱 도메인을 가져오면 린트 오류(`everp/domain-boundary` 의 공통 코드 목록에 `packages/`).
5. 첫 로드 JS 가 예산 안(묶음 import 라도 안 쓰는 컴포넌트는 빠진다).
6. 테스트, 빌드, e2e 통과.

## 결정 (AI 가 정함)

1. 라이브러리 빌드(tsup, Vite lib mode)는 아직 하지 않는다. 쓰는 앱이 하나라 소스를 바로 가져오는 편이 빌드 단계와 캐시 문제를 줄인다. 두 번째 앱(포털)이 생기면 다시 본다.
2. 순수 이동이라 새 동작 테스트는 없다. 옮긴 컴포넌트의 기존 테스트 18개가 패키지 안에서 그대로 돈다.

## 결과

1. `scripts/codemods/move-to-ui.py` 가 25개 컴포넌트와 테스트 5개를 git mv 하고 앱 파일 75개의 import 를 바꿨다. 손으로 고친 것은 패키지 설정, 린트 설정, `CommonType` 재내보내기.
2. 테스트: 앱 309 + ui 18 + 플러그인 21 = 348(옮기기 전과 같은 수). 워크스페이스 테스트에 `@everp/ui` 확인 추가.
3. 첫 로드 JS: 라우트마다 -0.6 ~ +0.4KB. 예산 안.
4. 확인: lint 0 errors(경고 459), tsc, build, e2e 59 통과 2 skip.
5. 남은 것: 앱 모델에 묶인 컴포넌트를 props 로 풀어 옮기기, 달력(날짜 유틸 패키지), Storybook(다음 카드).
