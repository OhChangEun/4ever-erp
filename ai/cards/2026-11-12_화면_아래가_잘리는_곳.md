## 현상

`/sales` 매출 분석 탭은 차트가 세 개(월별 매출 추이, 제품별 매출 비중, 주요 고객별 매출)인데 아래 두 개가 화면 아래로 잘리고 스크롤도 안 된다. 잘라내는 요소는 공통 `TabNavigation` 의 탭 내용 칸이다(`src/app/components/common/TabNavigation.tsx:74`, `flex-1 min-h-0 mt-4 flex flex-col overflow-hidden`). 목록 탭은 표가 남은 높이에 맞춰 줄고 표 안에서 스크롤하도록 짜여 있어 이 칸이 넘치지 않는다. 표가 아닌 내용은 줄지 않아서 넘친 만큼 잘린다.

전수 조사(2단계에서 쓴 `e2e/clipped-content.spec.ts` 를 고치기 전 코드로 돌린 결과). 비공개 화면과 탭, 하위 탭 31개, 화면 안 전환 8개, 모달과 팝업 34개를 두 창 크기에서 열었다.

2. 부서관리는 카드 격자다. 목은 부서가 하나라 안 넘친다. 응답의 부서를 24개로 늘리면(`page.route`) 같은 칸에서 같은 식으로 잘린다. 카드 격자, 차트, 폼처럼 줄지 않는 내용은 데이터가 늘면 어느 탭이든 잘린다는 뜻이다.

## 완료 기준

1. 비공개 화면과 탭, 하위 탭 전부에서 1280x720, 1512x772 둘 다 "내용이 잘렸는데 볼 방법이 없는 곳"이 0 이다. 판정: `overflow` 가 hidden 이나 clip 인 요소의 scrollHeight(scrollWidth)가 clientHeight(clientWidth)보다 4px 넘게 크고, 넘친 안쪽 요소와 그 요소 사이에 스크롤 칸이 없다. 글자 말줄임, 입력칸, svg 안, 1px 이하 요소는 뺀다.
2. 화면마다 대표 모달(상세, 등록 폼)과 사이드바 팝업에서도 0 이다. fixed 요소가 화면 밖으로 나간 것도 잘린 것으로 본다.
3. 표가 아닌 긴 내용의 탭은 탭 내용 칸이 세로로 스크롤된다. 부서 카드 24개에서 마지막 카드까지 내려갈 수 있다.
4. 목록 탭은 그대로다. 표 머리가 고정되고 표 안에서 스크롤하고 페이지네이션이 바닥에 있다. 스크롤되는 칸 안에 같은 방향으로 스크롤되는 칸이 또 있는 곳(이중 스크롤)이 0 이다.
5. 탭 내용 칸은 키보드로 스크롤된다. 포커스를 받고 이름이 있는 영역이다. 매출 분석 탭에서 End 로 끝까지 내려가고 바깥 화면은 같이 움직이지 않는다. 그 상태에서 axe critical, serious 0.

## 결정 질문 (게이트 1)

브리프에 답이 없어 AI 가 정한 것. `ai/decisions.md` "카드 화면 아래가 잘리는 곳 (AI 결정)" 행.

1. 어디서 스크롤하나. a `TabNavigation` 내용 칸 하나를 `overflow-auto` 로 / b 탭마다 `overflow-auto` / c 바깥 `main` 이 스크롤하게 화면 높이 고정을 푼다. a. 한 줄로 여섯 화면의 모든 탭이 고쳐지고 목록 탭은 `flex-1 min-h-0` 으로 줄어 이 칸이 넘치지 않으니 동작이 그대로다. c 는 목록 탭의 표 머리 고정과 바닥 페이지네이션이 깨진다.
2. 하위 탭(`SubNavigation`) 내용 칸도 스크롤 칸으로 만들까. 안 만든다. 스크롤 칸이 둘이면 키보드 처리도 두 곳이고 이중 스크롤 위험이 생긴다. 넘치면 하위 탭 버튼 줄이 내용과 같이 올라간다(부서관리 24개에서 확인). 버튼 줄을 고정해야 하면 그때 `sticky` 로.
3. 키보드 접근. a 내용 칸에 늘 `role="region"`, `aria-label`(활성 탭 이름), `tabIndex={0}` / b 넘칠 때만 붙인다 / c 안 붙이고 안쪽 버튼에 포커스가 가면 스크롤되는 것에 기댄다. a. b 는 넘침을 재려면 내용이 바뀔 때마다(데이터 도착, 탭 전환, 창 크기) ResizeObserver 와 MutationObserver 로 다시 재야 하고 state 와 effect 가 공통 컴포넌트에 들어간다. c 는 로딩이나 오류 상태처럼 포커스 받을 요소가 없는 탭에서 Safari 키보드 사용자가 못 내려간다. a 의 값: 탭 화면마다 Tab 정지가 하나 는다(통계 띠 기간 버튼과 툴바 사이). 포커스 링은 앱 공통 `:focus-visible` 이 그린다.
4. `scrollbar-gutter: stable`. 안 쓴다. 쓰면 스크롤바가 자리를 차지하는 환경(Windows)에서 스크롤이 없는 목록 탭까지 오른쪽이 늘 15px 비어 탭 줄, 통계 띠와 오른쪽 끝이 어긋난다. 안 쓰면 매출 분석 탭에서 차트가 뜰 때 폭이 한 번 15px 줄고 Recharts 가 한 번 다시 그린다. 늘 보이는 어긋남보다 한 번의 다시 그리기가 낫다. macOS 는 겹쳐 뜨는 스크롤바라 둘 다 해당 없다.
5. 재무 현황 탭의 자체 스크롤 래퍼(`flex-1 min-h-0 overflow-y-auto`)를 지운다. 공통 칸이 스크롤하니 필요 없고, 두면 스크롤 규칙이 두 가지가 되고 그 래퍼는 포커스도 이름도 없다.
6. 조사 스펙의 범위. 개발 서버에만 뜨는 TanStack Query 개발 도구 버튼(svg 가 48px 칸을 넘는다)은 판정에서 뺀다(운영 빌드에는 없다). 목 데이터가 적어 안 드러나는 카드 격자는 부서 응답을 24개로 늘린 테스트 하나로 본다. 판정 함수가 조용히 아무것도 못 잡게 되면 스펙 전체가 가짜 초록이 되므로 잡을 것 둘과 넘길 것 셋을 고정한 테스트를 하나 둔다.

## 결과 (6단계)

1. 고친 곳은 두 파일이다. `src/app/components/common/TabNavigation.tsx` 의 내용 칸을 `overflow-hidden` 에서 `overflow-auto` 로 바꾸고 `role="region"`, `aria-label`(활성 탭 이름), `tabIndex={0}` 을 줬다. `src/app/(private)/finance/components/overview/FinanceOverview.tsx` 의 자체 스크롤 래퍼를 지웠다.
2. 못 고친 것 없음. 모달과 가로 잘림은 고칠 곳이 없었다.
3. 7절 체크리스트 8개: 새 state 와 effect 없음, 데이터 출처 추가 없음, 새 컴포넌트 없음, 비동기 추가 없음, memo 추가 없음, `any`, `as`(스펙의 `as const` 제외), `!`, eslint-disable 없음, 기존 테스트는 손대지 않았다.
4. 확인: `pnpm exec tsc --noEmit -p .` 통과, `pnpm exec eslint . --max-warnings 0` 통과, `pnpm exec vitest run` 137 파일 1119 통과, `pnpm build` 통과, `pnpm bundle:check` 예산 안. build 뒤 `next-env.d.ts` 두 개 되돌림.
5. 문서: `ARCHITECTURE.md` 6절에 "화면 틀과 스크롤" 8줄, `DESIGN_GUIDELINES.md` 화면 뼈대에 스크롤 한 줄.
6. 블로그 소재: 잘린 곳을 사람 눈 대신 판정 함수로 찾고 그 스크립트가 그대로 회귀 테스트가 된 것. `scrollHeight > clientHeight` 와 `overflow: hidden` 만으로 화면 상태 73개(탭 31, 화면 안 전환 8, 모달과 팝업 34)를 창 크기 둘로 1분 30초에 훑는다.
