# 커스텀 ESLint 규칙 3개: 도메인 경계, 컴포넌트 useMutation, 임의 색

- 출처: 계획 16-1 "커스텀 ESLint 플러그인", 결정 기록 "커스텀 ESLint 플러그인" 행(규칙 3개)과 "전면 FSD" 행(import 방향과 도메인 index.ts 두 개만 린트로 강제)
- 우선순위: 4(규칙을 문서가 아니라 린트로 지킨다), 1(무효화를 mutation 훅 한 곳에 모은 구조를 지킨다)
- 브랜치: feat/ESLint_규칙_3개
- 크기: 반나절

## 현상

1. ARCHITECTURE 6절의 "도메인끼리 import 하지 않는다"는 문서 규칙이다. 지금 다른 도메인의 깊은 경로를 가져오는 import 가 24곳(4개 도메인의 이름 15개).
2. "컴포넌트에서 useMutation 을 직접 부르지 않는다"(mutation 훅 블록)도 문서 규칙이다. 지금 0곳이지만 막는 장치가 없다.
3. DESIGN_GUIDELINES 의 색 토큰 밖 임의 색(`bg-[#2563EB]`)이 5곳.

## 영향 범위

린트 설정, `src/app/(private)/{purchase,low-stock,inventory,sales}/index.ts`(새 공개 API), import 24곳, 견적 등록 모달 버튼 2곳, 창고 3D 범례 3곳.

## 완료 기준

1. `eslint-rules/` 에 규칙 3개와 RuleTester 테스트.
   1. `everp/domain-boundary`: 도메인 A 의 파일이 도메인 B 를 가져올 땐 `@/app/(private)/B`(그 도메인의 index.ts)로만. 공통 코드(`src/lib`, `src/app/components` 등)는 도메인을 가져오지 않는다.
   2. `everp/no-component-mutation`: `useMutation` 은 `*.mutations.ts` 와 `src/lib/query/` 에서만 import.
   3. `everp/no-arbitrary-color`: className 에 `bg-[#...]`, `text-[rgb(...)]` 같은 임의 색 금지.
2. 세 규칙 모두 error 로 켜고 위반 0.
3. 도메인 공개 API 는 다른 도메인이 실제로 쓰는 이름만 내보낸다.
4. 창고 3D 범례 색은 장면과 같은 상수에서 읽는다(토큰으로 바꾸면 테마가 blue-600 을 바꿔 둬서 장면과 어긋난다).
5. 테스트, 빌드, e2e 통과. 공개 API 묶음으로 첫 로드 JS 가 늘지 않는다.

## 결정 (AI 가 정함)

1. 플러그인은 지금 레포 안 `eslint-rules/`(로컬 플러그인). 모노레포 카드에서 `packages/eslint-plugin` 으로 옮긴다.
2. "회색 위 하늘색" 같은 조합 규칙은 린트로 잡기 어렵다(배경이 부모에 있다). 이번엔 임의 색만.
