# 고객 수정 모달 고장과 출하 준비 무효화 누락

- 출처: effect 정리 2차를 준비하다 발견. 앞선 "컴포넌트 안 useMutation 0건" 보고가 `useMutation<` 제네릭 형태를 놓쳤다
- 우선순위: 2 사용자가 한 일을 잃지 않는다, 1 서버와 일치
- 브랜치: fix/고객_수정_모달과_출하_준비
- 크기: 반나절

## 현상

1. 고객 수정 모달(`CustomerEditModal.tsx`)은 입력이 안 된다. 폼 상태가 모달이 아니라 목록(`SalesCustomerList.tsx:73`)의 state 에 있고 처음 값이 `null` 이다. 입력 핸들러가 `prev` 가 null 이면 null 을 돌려줘 아무것도 바뀌지 않는다. 모달은 열 때 받은 props 를 계속 보여 준다. 저장하면 원래 값이 그대로 간다.
2. 저장 버튼이 요청 결과를 기다리지 않고 모달을 닫는다(`handleEditSave` 안의 `onClose()`). 실패하면 입력이 사라진다.
3. 고객 수정 뒤 목록을 무효화하지 않아 목록에 옛 이름이 남는다. 실패해도 `onSettled` 로 상세를 무효화한다.
4. 출하 준비 처리(`ShippingDetailModal.tsx:51`)는 무효화가 하나도 없다. 처리 뒤에도 생산 중 목록과 출하 대기 목록, 재고 통계가 옛 값이다. 이 API 는 영업 주문 상태를 바꾼다(`sales-orders/:id/status`).
5. 위 두 곳이 컴포넌트 안 `useMutation<…>` 으로 남아 있었다. 이전 카드의 grep 이 `useMutation(` 만 셌다.

## 완료 기준

1. 고객 수정 모달은 자기 폼 상태를 가진다(열 때 값으로 한 번 초기화). 입력하면 값이 바뀌고, 저장하면 바뀐 값이 PATCH 로 간다.
2. 저장은 성공했을 때만 모달을 닫는다. 실패하면 모달과 입력이 남고 오류를 알린다.
3. `useUpdateCustomer`(sales): 고객 목록과 그 고객 상세를 무효화. 목록의 `editFormData` 상태와 상세 모달을 거치던 setter 전달을 지운다(안 쓰는 변수 경고 1건 해소).
4. `useMarkReadyToShip`(inventory): 출하 관련 키 전부(`shippingKeys.all`), 재고 통계, 영업 주문 목록과 그 주문 상세(의도한 교차, 표에 적음).
5. 컴포넌트 안 `useMutation` 0건을 `useMutation[<(]` 로 다시 확인한다.
6. 테스트, 린트, 빌드, e2e 통과.
