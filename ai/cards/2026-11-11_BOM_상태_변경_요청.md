# BOM 상태 변경 요청

- 출처: 서버 계약 점검(생산)
- 구현: Claude(erp-dev)
- 브랜치: fix/bom

## 결정할 것

1. 버튼을 숨기는 조건. `NEXT_PUBLIC_API_MOCKING` 으로 가르면 e2e(`e2e/bom-conflict.spec.ts`, CI)와 Vercel 데모가 이 값 없이 서버 목으로 돌아 버튼이 사라진다. 실백엔드(`BACKEND_API_URL` 있음)일 때만 숨기기로 했다(AI 결정, `ai/decisions.md` "카드 BOM 상태 변경" 행).

## 결과

1. 실백엔드가 붙으면 BOM 상세의 상태 토글과 충돌 재현 버튼이 없다. `production/page.tsx` 가 `BACKEND_API_URL` 을 읽어 `ProductionClient` 에 주고, `BomStatusActionsContext` 로 `BomTab` 까지, 거기서 `showStatusActions` prop 으로 모달에 준다(모달은 ModalProvider 밑이라 컨텍스트가 안 닿는다). 서버 목과 MSW 에서는 예전과 같다.
2. 게이트웨이에 없고 화면도 안 쓰는 요청을 지웠다. `DELETE /boms/{bomId}`(`deletBomItem`, MSW 핸들러), `/mrp/planned-orders/detail/{id}`(`fetchMrpPlannedOrdersDetail`, 스키마, 타입 파일, MSW 핸들러), `/mrp/request-summary`(상수만 있었음). `openapi/everp.yaml` 의 해당 경로와 스키마 2개를 빼고 `pnpm openapi` 로 `openapi.gen.ts` 를 다시 만들었다. grep 으로 남은 참조 0건.
3. 테스트: `BomStatusActions.realBackend.test.tsx` 2개(실백엔드면 두 버튼 없음, 서버 목이면 있음). 고치기 전 "없음" 쪽 실패 확인. 기존 테스트는 새 필수 prop 만 넘기게 바꿨다(`BomDetailModal.status.test.tsx`, `production.i18n.test.tsx`). 생산 계약 테스트의 "MRP계획주문" 항목은 상세 대신 목록 응답을 검사한다.
4. 확인: tsc 통과, eslint 0/0, vitest 112파일 789개 통과, build 통과(`/production` 은 바꾸기 전처럼 ○ 정적), `CI=1 pnpm exec playwright test e2e/bom-conflict.spec.ts --project=chrome` 통과.

## 남은 것

1. 실제 BOM 상태 변경 API 는 백엔드와 합의해야 한다. 게이트웨이 `PATCH /scm-pp/pp/boms/{bomId}` 는 `BomCreateRequestDto{productName, unit, items}` 를 받아 `{statusCode, version}` 을 버린다(verified=false, 실서버 미확인).
2. `/production` 이 정적 페이지라 버튼 숨김 값은 build 때 굳는다. build 때 없고 실행 때만 넣으면 버튼은 보이지만, 누르면 프록시가 501 로 막는다(리뷰 반영 1).

## 리뷰 반영

리뷰: 작성자를 가린 Claude 리뷰어. P0, P1 없음.

1. P2 버튼 숨김은 build 때 굳고 devtools 로 보내는 PATCH 를 못 막는다. 프록시(`src/app/api/proxy/[...path]/route.ts`)가 인가 뒤에 요청마다 본다. `BACKEND_API_URL` 이 있고 PATCH 이고 경로가 `scm-pp/pp/boms/{bomId}` 면 업스트림에 보내지 않고 501. 테스트 3개(실백엔드면 501이고 업스트림 0건, 실백엔드여도 GET 과 하위 경로 PATCH 는 통과, 서버 목이면 지금처럼 통과). 고치기 전 501 테스트 실패 확인.
2. P3 `BomStatusActionsContext` 기본값을 false(값이 안 오면 숨김)로. 실화면은 `ProductionClient` 가 늘 넘겨 그대로다(`BomStatusActions.realBackend.test.tsx`, e2e). `BomTab` 을 따로 그리는 `production.i18n.test.tsx` 한 곳은 서버 목과 같은 값을 감싸 주게 바꿨다(검사 내용은 그대로).
3. P3 `ai/decisions.md` 를 prettier 로 정렬. 물결표 새로 생긴 것 0.
4. P3 `ARCHITECTURE.md` 7절 `BACKEND_API_URL` 행에 build 때 읽는 곳과 요청마다 읽는 곳을 적었다(prettier 가 표 폭을 다시 맞췄다).
5. P3 `openapi/everp.yaml` 의 PATCH `/boms/{bomId}` 와 `simulate-conflict` 에 서버 목 전용 설명을 달고 `pnpm openapi` 로 생성 타입을 맞췄다.
6. 확인: tsc, eslint 0/0, vitest 112파일 792개, build(`/production` ○ 그대로), `CI=1 pnpm exec playwright test e2e/bom-conflict.spec.ts --project=chrome --retries=0` 통과.
