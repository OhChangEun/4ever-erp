# 인증 4단계: OIDC 로그인, 토큰 갱신, 로그아웃 3종(로컬 Keycloak)

- 출처: 계획 8절 1, 2, 6번, BFF 문서 Part D Phase 2, 3(3-1 ~ 3-6). 결정 9(세션), 10(Keycloak), 11(데모 유지)
- 우선순위: 1 보안과 정합성(토큰은 서버에만, 갱신 경쟁으로 세션이 끊기지 않게, IdP 에서 끊은 세션은 앱에서도 끊김)
- 브랜치: feat/인증_4단계_OIDC_로그인
- 크기: 이틀(카드 상한)

## 현상

1. 로그인이 인증이 아니다. 데모 계정 표에 아이디가 있으면 통과한다(BFF 문서 N3).
2. 세션 저장소가 없다. IdP 토큰을 둘 곳이 없고, 서버가 세션을 먼저 끊을 수 없다(N2).
3. 프록시가 세션 JWT 자체를 Bearer 로 보낸다(N1). 실 API 는 IdP 토큰을 기대한다.

## 완료 기준

1. `AUTH_PROVIDER=oidc` 면 Authorization Code + PKCE 로 로그인한다. state, nonce 확인. 데모 모드(기본)는 그대로.
2. 쿠키에는 sid 만, IdP 토큰은 서버 저장소에. API 프록시는 IdP access token 을 Bearer 로 보낸다.
3. access token 만료 30초 전 갱신. 동시 요청이 와도 sid 당 refresh 1회. 실패하면 세션 삭제와 401.
4. 로그아웃 3종: 앱 세션 삭제, IdP 로그아웃(RP 시작), 백채널 로그아웃(IdP 가 끊으면 앱 다음 요청 401).
5. 단위 테스트(가짜 IdP)와 로컬 Keycloak e2e 로 확인. 데모 모드의 단위, e2e 전부 통과.

## 결정 (AI 가 정함, 사용자 2026-11-10 "끝까지 진행")

1. IdP 는 Keycloak 26.8.1(결정 10 의 25 대신). 2026-11 기준 최신 안정판보다 한 단계 아래, Java 21. 포트 8180(이 맥의 8080 은 다른 서버가 쓴다).
2. realm 설정은 레포(`dev/keycloak/everp-realm.json`)에, 비밀번호와 client secret 은 자리표시자. 실제 값은 git 에 안 올리는 `.env.keycloak`, `.env.oidc`.
3. 콜백 오류(state 불일치, 트랜잭션 쿠키 없음, 역할 없음)는 400 대신 `/login?error=` 로 보낸다. 사람이 보는 화면이라 이유를 문구로 보여준다. 세션은 만들지 않는다.
4. 역할이 여럿이면 역할 표 순서의 첫 번째(ALL_ADMIN 이 먼저). 표에 있는 역할이 없으면 로그인 거절.
5. OIDC 모드에선 데모 로그인(POST)을 404 로 막는다. 비밀번호 없이 역할을 고르는 길이 남으면 안 된다.
6. 메모리 저장소는 globalThis 의 Map(Next 가 proxy 와 라우트를 다른 번들로 만들어 모듈 변수가 따로 생긴다). 인스턴스 하나에서만 맞아 Vercel 은 데모 모드 유지. 15분 role 클레임 쿠키는 외부 저장소를 붙일 때.
7. OIDC e2e 는 CI 에서 돌리지 않는다(Keycloak 없음). 로컬 확인 결과를 카드에 남긴다. 단위 테스트는 MSW 로 만든 가짜 IdP(RS256 키, discovery, JWKS, 토큰 엔드포인트)로 CI 에서 돈다.

## 결과

1. `src/server/auth/`: `config.ts`, `idp/`(인터페이스, OIDC 클라이언트), `session/memoryStore.ts`, `session/refresh.ts`(single-flight), `oidcLogin.ts`. 라우트: `/api/auth/login` GET(302), `/api/auth/callback`, `/api/auth/backchannel-logout`. `/api/auth/logout` 은 IdP 로그아웃 주소를 돌려준다. 로그인 화면은 OIDC 모드면 버튼 하나.
2. 테스트는 구현과 같이 썼다(빨간 테스트 커밋을 따로 두지 못함). 단위 21개 추가: OIDC 클라이언트 6(가짜 IdP), 로그인 흐름 8(state 위조, 콜백 재사용, 역할 없음, 외부 returnTo, 백채널 성공과 위조), 갱신 3(동시 5개에 refresh 1번, 실패 시 세션 삭제), 저장소 4.
3. 로컬 Keycloak 26.8.1 e2e 5개 통과(`npm run e2e:oidc`, 1.1분): 로그인 뒤 쿠키는 43자 sid 하나이고 `document.cookie` 에 안 보임, 재무 관리자의 인사 API 403, 60초 토큰을 두 번 넘겨도 동시 요청 5개 200, RP 로그아웃 뒤 다시 Keycloak 로그인 화면, Keycloak 관리 API 로 세션을 끊으면 다음 요청 401.
4. 데모 모드: 단위 242 통과, 빌드 통과, e2e 41 통과. ESLint 경고 478 그대로, 에러 0.
5. 한계: 메모리 저장소라 인스턴스 하나에서만 맞다. Vercel 은 데모 모드. 외부 저장소와 15분 role 클레임 쿠키는 실서버가 생길 때.
