# 문제 카드

erp-loop 의 입력 단위. 파일 하나 = 카드 하나. 이름은 `YYYY-MM-DD_<문제 이름>.md`. 문제 이름은 평문(예: `발주_승인_뒤_통계_카드_미갱신`). 번호나 코드는 쓰지 않는다.

템플릿:

```markdown
# <문제 이름>

- 출처: 리팩토링 15문제 표 / 새 버그 / 새 기능 / 리뷰 결함
- 우선순위: 1 서버와 일치 | 2 입력 보존과 실패 노출 | 3 체감 속도 | 4 유지보수성 (해당하는 것)
- 브랜치: refac/<문제>
- 크기: N일 (상한 3)

## 현상

무엇이 어떻게 잘못 보이나. `파일:줄` 앵커.

## 재현

MSW 핸들러를 어떻게 바꾸면 나는가. 단계별.

## 영향 범위

도메인, 쿼리 키(`*.keys.ts` 의 어떤 키), 공통 컴포넌트, 인증 경로.

## 완료 기준

1. 검증 가능한 문장. "…하면 …가 N초 안에 …된다."
2. …

## 남길 수치

무엇을 어떻게 재서 전후를 비교하나. 측정 명령.

## 결정 질문 (게이트 1)

1. 질문. 선택지 a / b. 추천 a, 이유.
   (없으면 "결정할 것 없음")

## 테스트 (2단계)

완료 기준 → 테스트 파일 대응표.

## 전후 표 (3단계)

| 항목 | 전 | 후 | 측정 방법 |

## 별도 보고

카드 범위 밖에서 발견한 것. 손대지 않음.

## 리뷰 (4단계)

`ai/reviews/<파일>` 링크. 돌려보낸 P0, P1 과 처리.

## findings (5단계)

| 완료 기준 | 결과 | 확인 방법 | 비고 |

## 결과 (6단계)

통과 여부, 수치 후보, 블로그 소재, 거절한 제안.
```
