# 재고 화면 코드값 표시와 입출고 아이콘

- 출처: i18n 6 결과 4
- 구현: Codex, 리뷰: Claude(역할 교대)

## 결정할 것

없음. 응답 코드 집합을 확정할 수 없는 부분은 표시 단계에서 호환하고 서버 값은 유지한다.

## 근거

- 팀 백엔드 읽기 전용 사본의 `_4EVER_BE_GW/src/main/java/org/ever/_4ever_be_gw/scm/im/dto/WarehouseCreateRequestDto.java`와 `WarehouseUpdateRequestDto.java`는 창고 요청 유형을 `MATERIAL`, `ITEM`, `ETC`로 명시한다. `scm/mm/controller/MmController.java`의 카테고리 필터도 `ALL`, `MATERIAL`, `ITEM`, `ETC`다.
- `scm/im/controller/ImController.java`의 재고 목록, 상세, 이동 기록과 창고 조회는 응답 본문을 문자열로 프록시한다. 이 사본과 ALARM에서는 실제 재고 응답 enum을 확인할 수 없었다. 주석 처리된 mockdata 컨트롤러를 실제 서버 응답의 근거로 사용하지 않았다.
- `openapi/everp.yaml`의 `InventoryResponse.category`, `warehouseType`, `InventoryDetailResponse.category`, `StockMovement.type`, `StockMovementResponse.type`은 enum 없는 string이다. 계약을 좁히거나 서버가 특정 값을 보낸다고 단정하지 않았다.
- 기존 MSW의 `MOTOR`, `BEARING`, `RAW`, `IN`, `OUT`과 카드 예시 `RAW_MATERIAL`은 표시 호환 대상으로 처리했다. 이동의 `MOVE`, `TRANSFER`, 한국어 `입고`, `출고`, `이동`도 함께 지원한다.

## 결과

1. 분류와 창고 유형을 그대로 렌더링하던 재고 목록, 재고 상세, 창고 목록, 창고 상세에 공통 표시 매핑을 적용했다. 기존 status의 MATERIAL, ITEM을 재사용하고 나머지는 ko와 en에 함께 추가했다. 분류 배지는 StatusLabel, 나머지는 일반 텍스트다. 모르는 코드와 기존 한국어 분류는 원문을 유지한다. 옵션 값, API 데이터와 요청에는 변환을 적용하지 않았다.
2. 한국어만 해석하던 이동 아이콘, 색상, 라벨, 상세 출발지와 도착지 조건을 표시용 해석 함수로 통일했다. 서버가 보내는 형식은 확정하지 않았다.
3. 재현 테스트는 inventory.defects.test.tsx 9개, warehouse.defects.test.tsx 2개다. 수정 전 라벨 미표시와 빈 아이콘으로 실패했다. 상세 기록 테스트는 출발지와 도착지 누락으로 실패한 것도 별도로 확인했다. 수정 후 11개 통과.

## 카드 밖에서 발견한 것

- 창고 수정 모달은 목 응답의 RAW를 선택할 옵션이 없다. 요청 DTO의 MATERIAL, ITEM, ETC만 있어서 기존 유형이 선택되지 않는다. 별도 계약 정리가 필요하다.
- 재고 상세 이동 기록은 note를 참조 번호 옆과 다음 줄에 중복 표시한다.
