# 인사 화면 결함

- 출처: i18n 7 결과 5
- 브랜치: fix/인사\_화면\_결함
- 우선순위: 1(화면이 서버와 어긋남: 필터, 수정 실패), 2(경고 뒤 제출)

## 결정할 것

없음. 서버가 받는 값은 팀 백엔드 읽기 전용 사본(`_4EVER_BE_GW` HrmController)에서 확인했다.

- `GET /time-record` 는 `statusCode`(NORMAL, LATE 등) 조건을 받는다.
- `PATCH /program/{id}` 의 `statusCode` 는 `@NotBlank` 필수다.

## 결과

1. 근태 상태 필터: 드롭다운 값이 조회 조건에 안 들어가 골라도 목록이 그대로였다. `statusCode` 로 보낸다(쿼리 키에도 들어가 캐시가 섞이지 않는다). 변수 이름이 "급여 지급 상태"로 복사돼 있던 것도 고쳤다.
2. 교육 지정 모달: 프로그램을 안 고르면 경고를 띄우고도 빈 programId 로 제출했다. 경고 뒤 멈춘다.
3. 프로그램 수정 모달:
   - 고친 이름이 아니라 원래 이름이 비었는지 봐서, 이름을 지워도 그대로 보냈다.
   - 상태를 안 고르면 빈 statusCode 를 보내 서버가 400 으로 거절했다. 이름만 고치려 해도 실패하던 경로다. 지금 상태를 처음 값으로 둔다.
4. 교육 시간 입력: 글자 칸에 예시가 "8시간, 2일"이라 그대로 넣으면 `Number()` 로 NaN 이 갔다. 숫자 칸(min 1)으로, 예시는 "예: 8".
5. 교육 프로그램 카드의 온라인 여부가 boolean 그대로라 빈칸이었다. "온라인"/"오프라인".
6. 교육관리 하위 탭 id 가 근태관리 탭을 복사한 'attendance', 'leave' 였다. 'employeeTraining', 'programs' 로. 공통 `SubNavigation` 은 모르는 id(예전 주소)면 빈 화면 대신 첫 탭을 연다.
7. 테스트: `hrm/hrm.defects.test.tsx` 7개. 고치기 전 코드에서 6개 실패를 확인했다(7번째는 SubNavigation 대체 동작이라 옛 id 에서는 통과).
8. 남긴 것: 프로그램 추가 모달이 `isOnline: true` 고정(폼에 온라인 여부 칸이 없다. 칸을 더하는 건 화면 사양이라 별도 카드 후보).
