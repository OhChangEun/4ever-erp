# e2e 를 CI 에서 돌린다

- 출처: Playwright 카드(PR #12)의 후속. 결정 22
- 우선순위: 1 화면이 서버와 어긋나지 않는다(머지 전 화면 회귀를 잡는다), 4 유지보수성
- 브랜치: refac/e2e_CI_연결
- 크기: 반나절

## 현상

1. e2e 38개가 로컬에서만 돈다. PR 은 단위 테스트와 빌드만 보고 머지된다. 화면 회귀(목록 갱신, 409 안내, 낙관적 반영)는 사람이 로컬에서 돌려야 잡힌다.
2. Playwright 설정은 `next dev` 를 띄운다. CI 에서는 페이지마다 처음 컴파일이 돌아 느리고, 빌드 결과와 다른 코드를 시험한다.

## 완료 기준

1. CI 의 기존 잡(`lint, type-check, test, build`) 안에서 빌드 뒤 e2e 를 돌린다. 머지 조건이 그대로 이 체크 하나라 merge 스크립트를 바꾸지 않는다.
2. CI 에서는 방금 만든 빌드를 `next start` 로 띄운다. 로컬은 지금처럼 `next dev` 와 기존 서버 재사용.
3. 브라우저는 러너에 설치된 Chrome(`channel: 'chrome'`). 브라우저 다운로드 없음.
4. 실패하면 trace 와 스크린샷을 artifact 로 올린다.
5. 로컬에서 `CI=1` 로 같은 명령이 통과한다. PR 의 CI 가 통과한다.

## 결정 (AI 가 정함, 사용자 2026-11-10 "끝까지 진행")

1. Vercel preview 대상이 아니라 CI 안에서 빌드한 서버를 쓴다. preview 는 배포 보호 우회 토큰이 필요하고 배포를 기다려야 한다. 서버 목은 두 경로가 같다.
2. CI 재시도 0. 재시도는 흔들리는 테스트를 가린다(우선순위 2, 실패를 숨기지 않는다). 흔들리면 테스트를 고친다.

## 결과

1. CI 잡 `lint, type-check, test, build` 에 빌드 뒤 `npm run e2e` 단계와 실패 시 `test-results/` artifact 업로드를 붙였다. 잡 제한 15 → 25분.
2. `playwright.config.ts`: `CI` 면 `next start`, 서버 재사용 끔, `forbidOnly`. 재시도 0.
3. 로컬 `CI=1` 실행(빌드 뒤 `next start`): 38 통과, 2 skip, 1.2분.
