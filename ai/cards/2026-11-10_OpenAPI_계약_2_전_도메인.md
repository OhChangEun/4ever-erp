# OpenAPI 계약 2: 나머지 도메인을 변환 스크립트로 옮기기

- 출처: OpenAPI 계약 1 카드의 다음 단계. 결정 기록 "대량 마이그레이션 방식"(codemod, 실패 케이스 수 기록)
- 우선순위: 1(타입, 목, 계약이 한 원본), 4
- 브랜치: feat/OpenAPI_계약_2_전_도메인
- 크기: 1일

## 현상

1. 계약에는 창고 요청 6개만 있다. 나머지 9개 api 파일의 요청 138개는 손 타입과 MSW 목만 있다.
2. 손으로 옮기면 경로, 메서드, 필드를 틀리기 쉽다.

## 영향 범위

`*.api.ts` 9개 파일이 부르는 요청 전부, 그 응답과 요청 본문 타입이 선언된 `types/` 파일, MSW 목(바꾸지 않고 계약으로 검사만). 화면 동작과 쿼리 키는 그대로.

## 완료 기준

1. 변환 스크립트 `scripts/codemods/api-to-openapi.mts` 가 api 파일을 타입 검사기로 읽어 계약에 경로와 스키마를 쓴다. 못 푼 호출 수를 적는다.
2. api 파일이 쓰는 엔드포인트 상수가 전부 계약에 있다(테스트).
3. 계약의 GET 응답 전부가 MSW 응답과 맞는다(테스트). 맞지 않는 곳은 목이나 계약 중 틀린 쪽을 고치고 카드에 적는다.
4. 계약에서 만든 타입(`npm run openapi`)이 drift 검사를 통과한다.
5. 손으로 쓴 응답, 요청 타입 선언은 생성 타입의 별칭이 된다(두 번째 변환 단계). 별칭으로 못 바꾼 것은 이유와 함께 적는다.
6. 테스트, 빌드, e2e 통과.

## 남길 수치

계약 경로 수, 스키마 수, 못 푼 호출 수, 별칭으로 바꾼 선언 수, 계약 검사가 찾은 목 불일치 수.

## 결정 (AI 가 정함)

1. MSW 목은 openapi-msw 로 다시 쓰지 않는다. 계약의 GET 응답 전부를 런타임에 검사하는 테스트로 묶는다. 160개 핸들러를 다시 쓰는 비용에 비해 얻는 것이 타입 수준 검사 하나뿐이다. 새로 쓰는 핸들러는 openapi-msw 로 쓴다.
2. 쿼리 파라미터는 이번에 계약에 넣지 않는다. 화면의 쿼리 타입은 손 타입 그대로 둔다. 다음 카드.
