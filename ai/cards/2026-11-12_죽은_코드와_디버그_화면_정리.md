# 죽은 코드와 디버그 화면 정리

- 출처: 앞 카드들의 별도 보고(알림 UI 연결 1, 3, 4, 남은 표시 결함 3 의 2, 표 테두리 한 겹의 2, 목이 쓰기 결과를 따르게 13)와 조정자 브리프
- 우선순위: 4 유지보수성(아무도 부르지 않는 화면, 모달, 타입, 상수, 메시지 키를 지워 읽을 코드를 줄인다). `/alarm` 은 주소로 들어갈 수 있던 디버그 화면이라 2 실패 노출과도 닿는다
- 브랜치: `chore/죽은_코드_정리`
- 크기: 1일
- 구현: Claude(erp-dev)

## 현상

1. `/alarm` 은 디버그 화면이다. `src/app/(private)/alarm/AlarmList.tsx:24` 에 `http://localhost:8080/api/alarm/notifications/subscribe/<사용자 id>` 가 박혀 있고 한국어 문자열과 console 로그가 그대로다. 메뉴(사이드바, 정책 표 `ACCESS_AREAS`)에는 없지만 로그인한 누구나 주소로 들어가 200 을 받는다. 알림은 PR #121 부터 사이드바에서 본다.
2. `src/app/components/header/Navigation.tsx` 는 화면에서 안 쓰고 `src/app/components/components.i18n.test.tsx:16,104` 만 가져다 쓴다.
3. 아무도 열지 않는 모달과 컴포넌트 7개(견적 신규 등록, 출결 수정, 직급 상세, MPS 미리보기, 프로필 머리, 헤더 프로필 드롭다운, 헤더 메뉴)와 그것만 쓰던 타입, API 함수, 쿼리 키, 상수, 메시지 키가 남아 있다.
4. 코드에서 안 쓰는 메시지 키 39개(ko, en 같이). 알려진 것은 `sales.chart.money`, `warehouse.warehouseType.MATERIAL`, `ITEM`, `ETC`.
5. 쓰는 곳 없는 엔드포인트 키 11개(`NOTIFICATION_ENDPOINTS.READ_LIST`, `HRM_ENDPOINTS` 10개), 어디서도 참조하지 않는 내보낸 타입 55개, 값을 안 읽는 `React` 기본 import 11곳, `StockMovement.tsx:25` 의 `border border`.

## 재현

1. `pnpm dev` 뒤 관리자로 로그인해 `/alarm` 을 열면 디버그 목록 화면이 뜬다(200).
2. `node scripts/unused-messages.mjs` 를 고치기 전에 돌리면 키 10개가 나온다(모달을 지운 뒤에는 39개).
3. `pnpm dlx knip --no-progress --reporter compact` 의 "Unused files" 19개 중 앱 코드 10개.

## 영향 범위

- 라우트: `/alarm` 이 없어진다. 앱의 `src/app/not-found.tsx` 가 404 로 답한다. 정책 표에는 원래 `/alarm` 행이 없었다(API 규칙 `alarm/notifications` 는 사이드바 알림이 쓰므로 남김).
- 도메인: 인사(직급 API 2, 직급 쿼리 키의 상세 2, 엔드포인트 10), 영업(견적 신규 등록 모달), 생산(MPS 미리보기 모달), 재무(목록 표 머리 상수). 쿼리 무효화 표(`*_MUTATION_EFFECTS`)는 바뀌지 않는다.
- 메시지: 공통 `profile.menu`, 인사 `positions` 전체와 `attendance` 3개, 생산 `mpsPreview` 전체, 영업 `newQuote` 전체와 `chart.money`, 창고 `warehouseType` 전체.
- 테스트와 도구: `e2e/clipped-content.spec.ts` 의 `/alarm` 행, `perf/bundle-baseline.json` 의 `/alarm` 행(기준선은 다시 재지 않고 그 행만 지움).
- 공통 컴포넌트: `packages/ui/src/PageTitle.tsx`(주석 한 줄만 남은 파일, `index.ts` 에 없음), `packages/ui/src/Table.tsx` 의 import 한 줄. 공개 export 는 그대로.

## 완료 기준

1. `/alarm` 으로 들어가면 Next 기본 404 가 아니라 앱의 not-found 화면(제목 "This page has not been generated")이 404 로 뜬다.
2. 코드에서 안 쓰는 메시지 키가 0 이다. 다음 카드가 화면을 지우고 키를 남기면 단위 테스트가 실패한다.
3. 정책 표의 페이지 목록에 `/alarm` 이 없고 알림 API 규칙은 남는다.
4. `Navigation.tsx` 를 지워도 "역할에 따라 바뀐 메뉴 이름이 영어" 단언은 사이드바 메뉴를 대상으로 그대로 남는다.
5. 표의 "지움" 항목이 레포에 없고, `tsc`, `eslint --max-warnings 0`, `vitest`, `build`, `bundle:check`, 영향받는 e2e 가 통과한다.

## 결정 질문 (게이트 1)

조정자 결정(브리프):

1. `/alarm` 라우트는 지운다. 정책 표, 메뉴, e2e, 번들 기준선의 `/alarm` 행도 같이. 기준선은 다시 재지 않고 그 행만 지운다.
2. `Navigation.tsx` 는 지우고 그 테스트의 단언은 `SidebarNavigation` 으로 옮긴다.
3. 죽은 코드 찾기는 `pnpm dlx knip`(설치 없이 한 번)과 `tsc --noUnusedLocals`, grep. 테스트에서만 쓰는 공개 함수는 남긴다.
4. 안 쓰는 메시지 키는 ko, en 에서 같이 지운다. 동적 접두사 아래는 지우지 않는다. 찾는 스크립트 `scripts/unused-messages.mjs`(접두사는 상수)와 "안 쓰는 키 0" 단위 테스트.
5. git 이력에 남으니 그냥 지운다. `packages/ui` 의 공개 export 는 지우지 않는다.

AI 결정(브리프에 답이 없던 것. `ai/decisions.md` 같은 이름의 행):

1. 자기 파일 안에서는 쓰는 export(`*_MUTATION_EFFECTS`, `*MutationKey`, `*StatTitle`, `ACCESS_AREAS` 등)는 `export` 를 떼지 않는다. 코드가 줄지 않고, 무효화 표는 도메인마다 같은 모양으로 내보내는 것이 규칙이라 몇 도메인만 떼면 모양이 갈린다.
2. 아무도 참조하지 않는 `Schema<'이름'>` 별칭 타입도 지운다(손으로 쓴 interface 와 같이 55개). 계약(`openapi/everp.yaml`)과 생성 타입이 원본이고 별칭은 가져다 쓸 때만 의미가 있다. ARCHITECTURE 5-1절의 "선언 160개"는 이 카드 전 숫자다.
3. 출결 수정 모달(`AttendanceEditModal.tsx`)은 지우고 그 훅 `useUpdateTimeRecord` 와 API, 엔드포인트는 남긴다. 훅은 `hrm.mutations.test.tsx` 가 쓰는 공개 함수다(조정자 결정 3). 화면에서 출결을 고칠 길은 이 카드 전에도 없었다(별도 보고 2).
4. `HRM_ENDPOINTS.POSITIONS` 는 남긴다. 화면은 안 부르지만 목(`src/mocks/handlers/hrm.handlers.ts:113`)이 쓰고 목은 다른 카드 영역이다. 같은 이유로 `USER_ENDPOINTS.LOGIN`, `LOGOUT`, `USER_INFO`, `PRODUCTION_ENDPOINTS.QUOTATION_PREVIEW` 도 남긴다.
5. 쓰지 않는 의존성(`js-cookie`, `@types/js-cookie`)은 지우지 않는다. 코드가 아니라 lockfile 을 바꾸는 일이고 CI 가 `--frozen-lockfile` 이다. 별도 보고 4.
6. 메시지 판정 규칙(리뷰에서 판정 3 과 접두사 검사를 더함, 리뷰 절): 앱 소스의 문자열 리터럴(TypeScript AST)만 보고, 전체 키가 있거나 같은 파일에 앞부분(namespace)과 뒷부분이 둘 다 있으면 쓴 것으로 본다. 우연히 같은 글자가 있으면 안 쓰는 키를 놓칠 수 있지만 쓰는 키를 지우지는 않는 쪽이다. 키 조각을 다른 파일에서 넘겨받는 곳(재무 통계 카드 제목, 재무 탭, 전표 유형, 공급업체 분류, 영업 단위)은 동적 접두사에 넣었다.
7. (리뷰에서 바뀜) `ProfileDropdown.tsx` 는 화면 컴포넌트(105줄)만 지우고 처음엔 이름을 그대로 뒀다. 리뷰 진4 로 `src/app/components/header/roleLabel.ts` 로 옮겼다.
8. ARCHITECTURE 8-1절 성능 기준선 표(2026-11-10)의 `/alarm` 행은 그날 잰 기록이라 지우지 않고 "지움" 표시만 붙였다.
9. `SalesChart.tsx:163,208` 의 안 읽는 콜백 인자(`entry`, `name`)는 자리 때문에 있는 인자라 지우지 않았다.
