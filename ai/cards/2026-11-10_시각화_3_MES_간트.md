# 시각화 3: MES 작업지시 간트

- 출처: 계획 17-1 "생산: MES 작업지시 간트(라인별 타임라인, 지연은 색)", 17-2 규칙 3(키보드로 포커스 가능한 데이터 포인트는 간트만), 6(블로그 소재: React 와 D3 의 DOM 소유권)
- 우선순위: 2(지연을 숨기지 않는다), 3(차트는 첫 로드에서 뺀다), 4
- 브랜치: feat/시각화_3_MES_간트
- 크기: 1일

## 현상

1. MES 목록은 표만 있다. 어떤 작업이 겹치는지, 무엇이 늦었는지 날짜 칸을 하나씩 읽어야 안다.
2. 목의 MES 날짜가 2026년 1~4월에 몰려 있어 오늘 기준의 일정이 보이지 않는다.

## 완료 기준

1. 목 MES 날짜를 오늘 기준 상대 날짜로(시작 오늘-14일~~오늘, 기간 5~~12일). 진행 중인데 끝날이 지난 건이 생긴다.
2. MES 탭에 "표 | 간트" 전환. 간트는 지금 페이지의 작업지시(최대 10건)를 줄마다 막대로: 시작~끝, 진행률만큼 채움, 오늘 선, 날짜 눈금.
3. 지연(진행 중이 아닌 완료가 아니고 끝날 < 오늘)은 빨간 테두리와 "지연" 글자. 색만으로 말하지 않는다.
4. D3 는 계산(시간 축, 눈금)만 하고 DOM 은 React 가 그린다. 계산은 순수 함수 `ganttLayout` 으로 테스트한다.
5. 키보드: 막대 목록(`role="list"`)에서 위아래 화살표, Home/End 로 옮기고(roving tabindex), Enter 나 Space 로 상세(기존 MES 현황 모달)를 연다. 막대 이름은 "번호 품목, 시작~끝, 진행 N%, 지연".
6. 간트 코드는 `next/dynamic` 으로 전환할 때만 받는다. 첫 로드 JS 예산 안.

## 결정 (AI 가 정함)

1. D3 는 `d3` 패키지(이미 의존성)의 `scaleTime` 과 `timeDay` 만. 축 그리기(`d3-axis`)는 쓰지 않는다. DOM 을 D3 가 만지면 React 와 소유권이 겹친다.
2. 줄 단위는 작업지시 하나. 계획의 "라인별"(생산 라인) 묶음은 MES 응답에 라인 필드가 없어 하지 않는다(verified=false 에 적는다).
