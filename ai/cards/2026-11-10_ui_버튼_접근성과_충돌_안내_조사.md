# @everp/ui 버튼 접근성과 충돌 안내 조사

- 출처: i18n 12 결과 7
- 구현: Codex(ultra), 리뷰: Claude(역할 교대)

- 출처: `2026-11-10_i18n_12_ui.md` 결과 7
- 우선순위: 2(보조 버튼의 의도치 않은 제출), 접근 가능한 조작과 올바른 충돌 안내

## 결정할 것

없음. 서버 값이나 API 계약은 바꾸지 않았다. 화면과 목의 값 충돌도 없어 백엔드 사본을 근거로 삼을 사안은 없었다. 문구는 기존 `UiText`, 앱 ko/en 메시지와 실제 `ConflictDialog` 호출부를 기준으로 했고, 제출 문제는 실제 폼의 클릭 동작으로 확인했다.

## 결과

1. `InputList` 삭제 버튼과 두 입력 팝업 연필 버튼은 접근 가능한 이름이 없었다. `UiText` 타입과 기본값, 앱 브리지, ko/en 메시지를 연결해 `aria-label`을 제공했다. 한국어와 영어 모두 이름으로 버튼을 찾아 삭제하거나 팝업을 열 수 있다.
2. `ModalStatusBox` 닫기와 `SimplePagination` 이전/다음 버튼은 기본 submit 버튼으로 동작했다. 세 버튼에 `type="button"`을 명시했다. 각 콜백은 호출되고 부모 폼은 제출되지 않는다.
3. 충돌 설명의 고정 조사 때문에 `창고을`, `견적서을`이 나왔다. 한글 음절의 종성에 따라 을/를을 고르는 함수를 기본값과 앱 번역이 공유한다. 실제 운영 호출부는 `BomDetailModal`의 `subject="BOM"` 하나다. 비한글은 기존 을을 유지해 BOM 한국어 문장은 같고, 영어 문구와 subject도 그대로다.
4. 테스트를 먼저 추가하고 실패를 확인했다. 이름 누락은 패키지 3개와 앱 6개, 폼 제출은 3개, 조사는 패키지와 앱 각각 2개가 해당 결함으로 실패했다. 조사 테스트 중 기존 BOM과 받침 있는 상품은 수정 전에도 통과했다. 충돌 VowelSubject와 상태 박스 Error의 Storybook play도 수정 전 실패, 수정 후 통과했다.
5. 검증: `pnpm exec tsc --noEmit -p .`, `pnpm exec eslint .`(오류 0, 경고 0), `pnpm exec vitest run`(95파일 586개), `pnpm build` 통과. `pnpm --filter @everp/ui test`(11파일 66개, Storybook play와 axe 포함), `build`, `check:lib`, `build-storybook` 통과. Storybook 빌드에는 use client 번들 경고가 있지만 종료 코드는 0이다. 빌드 뒤 루트와 포털의 `next-env.d.ts`를 HEAD 내용으로 복원했다.
6. 범위 밖으로 남긴 기존 문제: `InputList` 입력칸의 접근 가능한 이름 누락, 생산 도메인 전용 제목과 h1, `DropdownInputListModal`을 다시 열 때 부모가 갱신한 `initialItems` 미반영.
