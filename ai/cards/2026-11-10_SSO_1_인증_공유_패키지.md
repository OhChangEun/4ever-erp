# SSO 포털 1: BFF 인증 모듈을 공유 패키지로

- 출처: 계획 16-1 "SSO 두 번째 클라이언트: 코드는 BFF 모듈(8절)을 공유 패키지로 뽑아 재사용", 결정 29
- 우선순위: 1(인증 동작이 바뀌지 않는다), 4(두 앱이 같은 코드를 쓴다)
- 브랜치: refac/인증\_공유\_패키지
- 크기: 반나절

## 완료 기준

1. `packages/auth`(`@everp/auth`): OIDC 클라이언트, PKCE, 세션 저장소 경계(역할 타입을 제네릭으로), 메모리 저장소, single-flight 갱신, 트랜잭션 쿠키 서명, Next 로그인 흐름(`@everp/auth/next`), 가짜 IdP(`@everp/auth/testing`).
2. erp 는 어댑터만 남긴다: env 설정, 역할 고르기, 쿠키 이름과 속성, 데모 저장소.
3. 동작 변화 없음: 앱 단위 테스트, 패키지 테스트, 실제 Keycloak OIDC e2e 5개.

## 결정 (AI 가 정함)

1. 패키지는 'server-only' 를 import 하지 않는다. 쓰는 쪽의 진입 파일(설정, 세션)이 한다. 패키지 테스트가 Next 밖에서 돈다.
2. 메모리 저장소 레지스트리 이름을 인자로. 두 앱을 한 프로세스(테스트)에서 띄워도 세션이 섞이지 않게.
3. 로그아웃, 백채널 라우트는 앱에 둔다(짧고 쿠키 이름에 묶여 있다). 공통은 IdP 의 로그아웃 토큰 검증까지.

## 결과

1. 옮긴 파일 9개(git mv 로 이력 유지), 새 파일 `index.ts`, `next.ts`, `shortLived.ts`. erp 의 `oidcLogin.ts` 는 114줄 → 28줄.
2. 테스트: 앱 383 + auth 15(이전 앱 398 과 같음). OIDC e2e 5개 통과(로컬 Keycloak 26.8.1).
3. 같이 고친 것: OIDC e2e 의 재무 통계 경로가 `statistics` 였다. 계약 철자는 `statictics` 이고 목 한 벌(#39) 뒤로 404 가 나고 있었다(인증과 무관). 루트 tsconfig 가 `packages/ui/dist` 를 읽다가 같은 시간에 도는 ui 빌드와 겹쳐 타입 검사가 깨지던 것(#71 에서 생김)을 빌드 결과 제외로 막았다.
