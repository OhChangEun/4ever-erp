# i18n 1: next-intl 기반과 상태, 메뉴 영어

- 출처: 계획 16-1 "i18n: next-intl 로 한국어와 영어. STATUS_TEXT_MAP 이 이미 있어 그 자리에서 시작", 결정 30
- 우선순위: 3(정적 렌더와 첫 로드를 지킨다), 4(문구가 한 곳에)
- 브랜치: feat/i18n\_1\_기반
- 크기: 하루

## 완료 기준

1. next-intl, 메시지 `src/i18n/messages/{ko,en}.json`, 키 타입(ko 기준), ko 와 en 키가 같은지 테스트.
2. 상태 글자 57개(`STATUS_TEXT_MAP` 를 메시지로 옮김), 사이드바 메뉴, 탭 제목, 프로필 메뉴, 언어 전환(프로필 메뉴 안, 쿠키 1년).
3. 페이지는 정적 렌더 그대로(○). 첫 로드 증가를 재고 기록.
4. e2e: 영어로 바꾸면 메뉴와 상태가 영어, 새로고침 뒤에도 유지, 한국어로 되돌리기.
5. 남은 한국어 문자열 수를 재는 스크립트.

## 결정 (AI 가 정함)

1. URL 에 언어를 넣지 않는다(`/en/...` 없음). 로그인 뒤 화면이라 검색 노출이 필요 없고, 인가 표와 proxy matcher 의 경로 규칙을 바꾸지 않는다.
2. 서버는 한국어로 정적 렌더, 언어는 브라우저가 쿠키로 고른다. `decisions.md` 같은 날 행.
3. 이 카드는 기반까지. 도메인 화면의 문구는 도메인마다 다음 카드로 옮긴다(아래 수).

## 결과

1. `src/i18n/`(locale, IntlProvider, useSetLocale, request, global.d.ts, messages), `StatusLabel`, `SidebarNavigation`(`getNavLabelKey`), `TabNavigation`, `SidebarProfile`(언어 전환). `STATUS_TEXT_MAP` 과 `getStatusText` 를 지웠다. 테스트 렌더러에 한국어 provider.
2. 처음엔 레이아웃이 쿠키를 읽어 모든 페이지가 동적 렌더가 됐고, next-intl 런타임이 첫 로드 +14.5KB 였다. 브라우저 쪽 언어 고르기와 `precompile` 로 정적 렌더를 되찾고 +5.7KB 로 줄였다. 기준선 갱신.
3. 한국어 문자열: 2,193 → 2,123(`node scripts/count-hangul.mjs`). 많은 순: 생산 329, 영업 318, 인사 312, 재고 222, 구매 205.
4. 확인: verify(앱 399), e2e 72 통과 2 skip, 리뷰 지적 없음.
5. 남은 것: 도메인 화면 문구 2,123개, 날짜와 금액 형식의 언어별 처리(`formatCurrency` 는 ko-KR 고정), 로그인 화면의 잠깐 한국어(결정 2).
