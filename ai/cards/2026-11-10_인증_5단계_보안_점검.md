# 인증 5단계: 보안 점검을 테스트로 고정, __Host- 쿠키

- 출처: BFF 문서 Part D Phase 5(직접 공격 7가지), 계획 8절 7번(`__Host-` 접두사 결정)
- 우선순위: 1 보안
- 브랜치: refac/인증_5단계_보안_점검
- 크기: 반나절

## 현상

1. Phase 5 의 공격 점검(다른 출처 POST, 오픈 리다이렉트, 콜백 재사용, sid 위조, alg none, 경로 우회)이 사람이 손으로 하는 체크리스트다. 테스트가 없어 코드를 고치면 다시 열릴 수 있다. 같은 출처 판정(`sameOrigin.ts`)과 API 프록시 라우트에는 테스트가 하나도 없다.
2. 운영 세션 쿠키 이름이 `session` 이다. 같은 사이트의 다른 서브도메인이 같은 이름의 쿠키를 심어 바꿔치기(cookie tossing)할 수 있다.

## 완료 기준

1. 테스트로 고정: 같은 출처 판정 8가지, alg none 과 역할 표 밖 role 거절, 돌아갈 경로 8가지, 프록시(세션 없음 401, 쿠키 대신 Bearer, 역할 403, `..` 경로 정규화, 인코딩 경로 400, 다른 출처 POST 403). 콜백 재사용과 state 위조, sid 쿠키는 4단계 테스트가 이미 본다.
2. 운영 빌드의 세션 쿠키 이름은 `__Host-session`. 브라우저가 Secure, Path=/, Domain 없음을 강제한다. 개발(http)은 `session`.
3. 테스트, 빌드, e2e(CI 의 next start 는 운영 빌드라 `__Host-` 로 돈다) 통과.

## 결정 (AI 가 정함, 사용자 2026-11-10 "끝까지 진행")

1. `__Host-` 를 붙인다(계획 8절 7번의 결정 항목). 지금 운영 사용자는 배포 직후 한 번 다시 로그인한다(쿠키 이름이 바뀜). 데모 사이트라 받아들인다.
2. OIDC 트랜잭션 쿠키(`oidc_tx`)는 path 가 `/api/auth` 라 `__Host-` 를 못 쓴다. 10분짜리 서명 쿠키라 그대로 둔다.

## 결과

1. 보안 점검 테스트 30개 추가: 같은 출처 판정 8, 돌아갈 경로 8, alg none 과 역할 밖 role 2, 프록시 6(세션 없음 401, 쿠키 대신 Bearer, 역할 403, `..` 정규화, 인코딩 경로 400, 다른 출처 POST 403), 쿠키 이름과 삭제 속성 3, 운영 빌드 로그아웃 e2e 1. 기존 코드는 쿠키 삭제 외에 전부 통과했다.
2. 운영 세션 쿠키 `__Host-session`. 심을 때와 지울 때 같은 속성(리뷰 A1, P1).
3. 단위 269 통과, 빌드 통과, 운영 빌드 e2e 42 통과(`CI=1`).
