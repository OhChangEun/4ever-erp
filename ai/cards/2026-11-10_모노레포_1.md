# 모노레포 1: pnpm workspace, Turborepo, 첫 패키지(eslint-plugin)

- 출처: 계획 16-1 "모노레포: pnpm workspace + Turborepo", 결정 기록 "패키지 매니저"(pnpm 전환은 모노레포 카드에서), "모노레포"(packages 6개, 일부러 과함)
- 우선순위: 4
- 브랜치: chore/모노레포_1
- 크기: 1일

## 현상

1. npm 하나짜리 레포다. 로컬 ESLint 플러그인(`eslint-rules/`)이 앱과 같은 package.json 에 섞여 있어 경계가 문서뿐이다.
2. lint, 타입 검사, 단위 테스트를 매번 처음부터 돌린다. 바뀐 곳이 없어도 같다.

## 완료 기준

1. 패키지 매니저 pnpm 10(`packageManager` 고정). `package-lock.json` 을 `pnpm import` 로 옮겨 같은 버전을 유지한다.
2. `pnpm-workspace.yaml`: 앱은 루트에 그대로(Vercel 프로젝트 설정의 루트 디렉터리를 바꾸지 않으려고), 패키지는 `packages/*`.
3. 첫 패키지 `packages/eslint-plugin`(`@everp/eslint-plugin`). 앱은 `workspace:*` 로 가져온다. 규칙 테스트도 패키지 안으로.
4. Turborepo: lint, type-check, test 를 turbo 로 돌리고 결과를 캐시한다. CI 는 `.turbo` 를 캐시해 바뀌지 않은 패키지를 건너뛴다.
5. CI, Playwright 서버 명령, 문서의 명령을 pnpm 으로.
6. 테스트, 빌드, e2e 통과. 첫 로드 JS 그대로(번들 예산 검사).

## 결정 (AI 가 정함)

1. pnpm 10.34.8. 11, 12 도 있지만 Vercel 이 lockfile 로 버전을 알아보는 범위가 10 까지라 확실한 쪽.
2. 앱을 `apps/erp` 로 옮기는 것은 이번에 하지 않는다. Vercel 의 Root Directory 를 바꾸는 것은 대시보드 설정(외부)이라 사용자 확인이 필요하다. 루트 앱 + packages 로 시작한다.
3. 엄격한 node_modules(pnpm 기본)를 그대로 쓴다. 선언 안 하고 쓰던 의존성(phantom)은 package.json 에 적는다. `shamefully-hoist` 로 덮지 않는다.

## 결과

1. pnpm 10.34.8. `pnpm import` 로 package-lock 의 버전을 그대로 옮겼다(패키지 866개).
2. `packages/eslint-plugin`(`@everp/eslint-plugin`, 규칙 테스트 21개). 앱은 `workspace:*` 로 가져온다.
3. `pnpm verify` = turbo 로 lint, 타입 검사, 단위 테스트(루트 327), 패키지 테스트(21). 첫 실행 11.7초, 두 번째는 4개 모두 캐시 적중으로 8ms.
4. CI: pnpm/action-setup, `pnpm install --frozen-lockfile`, `.turbo/cache` 캐시, `pnpm verify`.
5. phantom 의존성 3개를 선언했다. 플러그인의 `@typescript-eslint/parser`, 앱의 `three-stdlib`(창고 3D 카메라)와 `@types/three`. 앱 쪽 둘은 로컬에서 못 찾았다. npm 시절 node_modules 가 남아 있어 통과했고, CI 의 새 설치에서 tsc 가 잡았다. 그 뒤로는 node_modules 를 지우고 `pnpm install --frozen-lockfile` 한 상태에서 전체를 다시 돌려 확인했다.
6. 확인: lint 0 errors(경고 459), tsc, vitest 327 + 21, build, 번들 예산 안(+0.1KB 이내), e2e 59 통과 2 skip.
7. 남은 것: Vercel 이 pnpm 으로 설치하는지는 하루 배포 제한이 풀린 뒤 확인(verified=false). 앱을 `apps/erp` 로 옮기기(Vercel Root Directory 변경 필요), packages/ui 와 Storybook, api-contract 패키지.
8. 사고: Dependabot 설정을 머지한 직후 Dependabot 이 PR #46~#51 을 열어 이 카드의 PR 번호가 #52 로 밀렸다. 머지 스크립트에 46 을 넘겨 Dependabot 의 #46(GitHub 공식 액션 3개 v4 → v7)을 리뷰 없이 머지했다. 그 PR 의 CI 는 통과했고 공식 액션 갱신이라 되돌리지 않았다. 머지 스크립트가 PR 의 브랜치 이름이 넘긴 이름과 같을 때만 머지하게 고쳤다(다른 PR 번호로 시험해 거부되는 것 확인). 이 카드의 커밋은 main 위로 다시 올려 새 브랜치 `chore/모노레포_1b` 로 PR 을 다시 열었다(force-push 를 피하려고).
