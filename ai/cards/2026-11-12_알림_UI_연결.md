- 출처: 새 기능(만들어 둔 알림 UI 가 어느 화면에도 안 붙어 있음)
- 우선순위: 1 서버와 일치(읽음 처리 뒤 목록과 안 읽은 수), 2 실패를 숨기지 않기(목록 실패와 다시 시도), 3 체감 속도(첫 로드 +5KB 한도)
- 브랜치: feat/알림\_UI\_연결

- 구현: Claude(erp-dev)

## 현상

알림 목록, 읽음 처리, SSE 구독 코드가 있는데 부르는 곳이 없다. 사용자는 알림을 볼 방법이 없다.

1. `src/app/components/header/Notification/NoificationDropdown.tsx`(110줄)의 `NotificationDropdown` 을 import 하는 파일이 0개다.
2. `useNotificationSSE.ts`(143줄)를 부르는 곳은 자기 테스트뿐이다.
3. 화면 틀은 왼쪽 사이드바(`src/app/components/sidebar/Sidebar.tsx`)이고 상단 `Header.tsx` 는 import 0건이다.
4. 사이드바는 `(private)/layout.tsx:17` 에서 그려지는데 `QueryClientProvider` 는 그 아래 도메인 레이아웃(`_RouteProviders.tsx`)에만 있다. 사이드바 안에서는 `useQuery` 를 쓸 수 없다.
5. 옛 드롭다운은 안 읽은 수를 지금 페이지 3건에서 셌다(`NoificationDropdown.tsx:59`). 다른 페이지의 안 읽은 알림은 빠진다.
6. 목 핸들러(`src/mocks/handlers/auth.handlers.ts:76-91`)는 목록, 개수, 읽음 처리가 서로 무관한 고정 값이다. 읽음 처리해도 개수는 늘 2 다.

## 완료 기준

1. 사이드바에 알림 버튼이 있다. 펼친 상태와 접힌 상태(w-16) 모두에서 보인다.
2. 안 읽은 수가 1 이상이면 숫자 뱃지가 보이고 99 를 넘으면 `99+` 다. 버튼 이름은 "알림, 안 읽은 알림 N개".
3. 안 읽은 수 조회가 실패하면 뱃지만 없고 버튼은 남는다.
4. 버튼을 누르면 사이드바 옆에 알림 목록이 팝오버로 뜬다(`role=dialog`, 목록은 list 와 listitem). 버튼에 `aria-haspopup`, `aria-expanded`. 바깥을 누르거나 버튼을 다시 누르면 닫힌다. 열려 있는 동안 `aria-controls` 가 팝오버를 가리킨다. 팝오버 폭은 화면 안에 묶인다.
5. 안 읽은 알림을 누르면 읽음 처리되고 뱃지 수가 1 준다. 전체 읽음을 누르면 뱃지가 사라진다.
6. 읽음 처리 mutation 은 목록 키와 안 읽은 수 키를 같이 무효화하고 다른 도메인 키는 건드리지 않는다.
7. 목록을 못 받으면 팝오버 안에 실패 문구와 다시 시도 버튼이 보이고, 누르면 다시 받는다.
8. 빈 목록은 "알림이 없습니다".
9. 읽음 처리가 실패하면 팝오버 안에 실패 문구가 보이고 뱃지는 그대로다.
10. Esc 로 닫히고 포커스가 알림 버튼으로 돌아온다. 알림을 읽은 뒤에도 포커스가 팝오버 안에 남는다.
11. SSE 가 꺼져 있거나 끊기면 60초마다 다시 받는다. 화면은 오류로 막히지 않는다.
12. SSE `alarm` 이벤트가 오면 알림 키(목록, 안 읽은 수)만 무효화한다.
13. 안 읽은 수가 늘면 `role=status` 로 "새 알림이 도착했습니다. 안 읽은 알림 N개" 를 알린다. 처음 받은 수는 알리지 않는다.
14. 영어 화면에서 버튼 이름, 팝오버 문구, 실패 문구가 영어다.
15. 프록시 인가 표가 알림 경로를 모든 역할에게 연다.
16. 목에서 목록, 안 읽은 수, 읽음 처리가 서로 맞는다.
17. 목록 응답과 개수 응답은 zod 로 검증하고 모양이 틀리면 형식 오류로 보인다. `linkType`, `linkId` 의 null 은 받는다. `source` 는 문자열이면 받고 모르는 값은 "알 수 없음"으로 보인다.
18. 팝오버를 연 상태에서 axe critical, serious 위반 0.
19. 라우트 첫 로드 JS 증가가 +5KB 안.

## 결정 질문 (게이트 1)

조정자가 정한 12개는 그대로 따랐다(사이드바 위치, 죽은 헤더 삭제, 계약 근거 규칙, OpenAPI 와 zod, 목, 쿼리 키, 실패 표시, 인가, i18n, 접근성, 번들, 그 밖은 AI 결정).

조정자 결정에 없어서 우선순위 표 순서로 스스로 정한 것:

1. 사이드바 전용 QueryClient. 사이드바는 도메인 레이아웃의 `QueryClientProvider` 밖이다. `(private)/layout.tsx` 에서 사이드바만 감싸는 클라이언트를 하나 더 만든다(같은 `createQueryClient`, 401 처리 같음). Provider 를 위로 올리는 안은 도메인 레이아웃 10개와 "메시지가 ModalProvider 바깥" 순서를 다 건드려 이 카드보다 크다. 알림 키는 사이드바만 쓰고 다른 도메인 mutation 이 알림 키를 무효화할 일이 없어 클라이언트가 둘이어도 화면과 서버가 어긋나지 않는다. 화면을 옮겨도 사이드바 클라이언트는 남아 안 읽은 수를 다시 받지 않는다.
2. 안 읽은 수는 `count?status=UNREAD` 로 명시해서 받는다. 게이트웨이 기본값은 없고 알림 서버 기본값(UNREAD)에 기대면 서버가 바뀔 때 조용히 전체 수가 된다.
3. SSE 는 `NEXT_PUBLIC_SSE_ENABLED=true` 일 때만 붙는다(기존 스위치 유지). 기본은 꺼짐이고 60초 폴링이다. Vercel 데모의 서버 목은 연결을 1.5초 뒤 닫아 매 화면에서 함수를 붙잡을 이유가 없다. 켜져 있을 때 끊기면 60초 뒤 다시 붙고 그동안 폴링한다. 401 은 다시 붙지 않는다(폴링이 401 을 받아 로그인으로 보낸다). 다시 붙을 때마다 알림 키를 무효화해 끊긴 동안 놓친 알림을 받는다.
4. 새 알림 알림(`role=status`)은 SSE 이벤트가 아니라 안 읽은 수가 늘었을 때 낸다. 기본이 폴링이라 SSE 이벤트에만 걸면 대부분의 환경에서 한 번도 안 울린다. SSE 로 와도 무효화 뒤 수가 늘어 같은 경로로 한 번만 울린다.
5. 알림 시각은 지금 형식 `YYYY.MM.DD HH:mm` 그대로(한국어, 영어 같음). 기존 테스트 2건(`components.i18n.test.tsx:127,141`)이 두 언어에서 이 형식을 고정하고 있어 바꾸면 기존 테스트를 고쳐야 한다. 상대 시간("3분 전")은 넣지 않았다. 팝오버를 열어 둔 동안 값이 굳어 서버 시각과 어긋나 보인다. 조정자 결정 9의 "상대 시간"과 다르게 간 부분이라 확인 필요. 조정자 확인(2026-11-12): 이 형식 유지.
6. `Navigation.tsx` 는 지우지 않았다. `components.i18n.test.tsx:16,104` 가 import 해서 쓰고 있어 지우려면 기존 테스트를 지워야 한다. `Header.tsx` 는 import 0건이라 지웠다. 조정자 확인(2026-11-12): 이번엔 두고 정리 카드에서.
7. `linkType`, `linkId` 는 null 을 받는다(계약 nullable, zod nullish). 알림 서버가 참조가 없는 알림에 null 을 넣는다. 화면은 두 필드를 쓰지 않아 null 하나로 목록 전체가 형식 오류가 되면 손해만 있다.
8. 목 상태는 요청의 `Authorization` 값별로 둔다. 프록시가 세션 토큰을 Bearer 로 붙여 로그인마다 새 상태가 된다. e2e 를 같은 dev 서버에서 여러 번 돌려도 안 읽은 알림이 바닥나지 않고, 한 사용자의 읽음 처리가 다른 사용자 뱃지를 바꾸지 않는다.
9. 읽음 처리 실패는 팝오버 안 한 줄(`role=alert`)로 보인다. 토스트는 도메인 레이아웃의 `ToastProvider` 안에서만 쓸 수 있다.
10. 알림 출처 표시를 색 배경 흰 글자 알약에서 회색 글자로 바꿨다. 노랑, 청록, 주황 배경의 흰 글자는 대비가 4.5:1 에 못 미쳐 axe serious 위반이다. 아이콘 색은 그대로다.
11. 페이지 이동은 공통 `SimplePagination`(@everp/ui)으로 바꾸고 `NotificationPagination.tsx` 는 지웠다. 옛 버튼은 아이콘만 있고 이름이 없어 axe critical 위반이다.
12. 읽은 알림은 버튼이 아니다. 눌러서 할 일이 없다(연결 화면 이동은 카드 밖). 안 읽은 알림만 버튼이고 읽음 요청이 가는 동안은 비활성이다. 공통 mutation 빌더가 진행 중 두 번째 호출을 버려서, 막지 않으면 두 번째 알림을 눌러도 아무 일이 없다.
13. SSE 구독 경로는 OpenAPI 계약에 넣지 않았다. 계약 테스트가 모든 GET 의 `application/json` 200 응답을 목과 맞춰 봐서 `text/event-stream` 을 넣으면 깨진다. 경로 상수와 이벤트 이름은 훅과 이 카드에 적었다.
14. 안 쓰게 된 `notification.sseError` 메시지 5개(ko, en)와 훅의 오류 상태를 지웠다. SSE 실패는 조용히 폴링으로 물러나서 보여 줄 곳이 없다.
15. 팝오버 내용 청크를 못 받거나(오프라인 등) 내용이 그리다 깨지면 팝오버 틀 안에 "알림을 불러오지 못했습니다." 가 보이고 화면은 그대로다. 사이드바는 `(private)/error.tsx` 경계 밖이라 그냥 두면 앱 전체 오류 화면이 된다. 공통 `ErrorBoundary` 로 감쌌다. 리뷰 뒤 테스트를 넣었다(`NotificationBell.chunk.test.tsx`). 한 번 실패하면 `React.lazy` 가 실패를 기억해 새로고침해야 다시 받는다.
16. 팝오버를 `PopoverPortal` 과 floating-ui 로 띄우지 않았다. 조정자 결정 1의 권고와 다르게 간 부분이라 확인 필요. floating-ui 판을 먼저 만들어 쟀더니 `FloatingFocusManager`(와 tabbable)가 드롭다운이 있는 화면 7곳의 첫 로드 청크로 들어가 +5.1KB 였다(같은 커밋 수정 전 대비, 한도 +5KB). 알림 버튼 바로 뒤 DOM 에 그리고 CSS(`absolute left-full bottom-0`)로 사이드바 오른쪽에 붙이는 쪽으로 바꿔 +2.3에서 3.3KB 가 됐다. portal 이 없어 Tab 순서가 버튼, 목록, 프로필로 그대로 이어진다. Esc 는 공통 `useCloseOnEscape`, 바깥 누름과 포커스 이동(열 때 팝오버로, Esc 때 버튼으로, 읽은 뒤 팝오버로)은 `NotificationDropdown.tsx` 가 한다. 사이드바는 왼쪽 아래 고정이라 뒤집기(flip)가 필요 없다. 모달이 열리면 사이드바 전체가 눌리지 않아 "모달 안 팝업" 문제도 없다. 속도(우선순위 3)가 공통 조각 재사용(4)보다 앞이라 이렇게 골랐다. 조정자 확인(2026-11-12): 이 방식 유지. 리뷰 뒤 틀과 닫기는 `NotificationBell.tsx` 로 옮겼다(결정 20).
17. 뱃지는 버튼 안이 아니라 버튼 위에 겹친 형제 요소다(`pointer-events-none`, `aria-hidden`). 버튼 안에 두고 `aria-label` 을 달았더니 axe 가 `label-content-name-mismatch`(serious, WCAG 2.5.3)로 잡았다. `aria-label` 을 빼고 보이는 글자와 숨긴 글자를 이어 이름을 만들면 크롬이 "알림 , 안 읽은 알림 3개"(쉼표 앞 공백)로 계산했다.

20. (리뷰 뒤) 팝오버 틀(dialog, id, 폭 상한)과 닫기(Esc, 바깥 누름, 포커스 복귀)를 `NotificationBell` 로 옮겼다. 내용 청크를 받는 중이거나 못 받았을 때도 닫히고, `aria-controls` 가 가리킬 요소가 누르자마자 있다. 첫 로드는 0.2KB 쯤 늘었다.

8. `/profile` 레이아웃은 본문 왼쪽 여백을 256px 로 잡는다(`src/app/(public)/profile/layout.tsx:21`). 사이드바 폭은 224px(w-56)이고 다른 화면은 224px 다.
9. ARCHITECTURE 5-1절 첫 줄의 계약 개수(경로 129, 요청 144, 스키마 165)는 지금 133, 147, 169 다(이 카드에서 스키마 2개 추가, 그 전에 이미 167).
10. 브라우저 MSW 모드(`NEXT_PUBLIC_API_MOCKING=enabled`)에서는 워커가 뜨기 전에 나간 첫 안 읽은 수 요청이 서버 목으로 간다. 두 목의 상태가 따로라 첫 숫자가 잠깐 다를 수 있다(다음 무효화에서 맞춰진다). 개발 모드에서만 생기고 실제로 띄워 보지는 않았다.
11. `Sidebar.tsx:15-26` 의 effect 가 1024px 미만에서 `isExpanded` 가 true 가 되면 바로 false 로 돌린다. 사이드바를 열자마자 닫혀 메뉴와 알림에 닿지 못한다. 이 카드 전부터 있던 코드이고 모바일은 SKIP 이다(ARCHITECTURE 9절). 코드로만 봤다.
12. 알림을 눌러도 `linkType`, `linkId` 가 가리키는 화면으로 이동하지 않는다. 지금은 읽음 처리만 한다. 다음 카드 후보.
13. `next/dynamic` 은 vitest 에서 pages 라우터 구현으로 풀려, 가져오기 실패가 오류 경계로 오지 않는다(결정 21). `ModalProvider.tsx:19` 의 모달 틀도 `next/dynamic` 이라 청크 실패 경로는 단위 테스트로 볼 수 없다. ARCHITECTURE 10절에 이미 미확인으로 적혀 있다.

## 확인하지 않은 것 (verified=false)

1. 알림 응답 본문 전부(위 "서버 계약 근거" 표의 verified=false 행). 실서버 응답 샘플이 필요하다.
2. 프록시(`/api/proxy`)를 거친 SSE 가 브라우저까지 끊기지 않고 오는지, 실서버가 `alarm` 을 보낸 직후 개수 API 가 이미 늘어 있는지. SSE 는 기본 꺼짐이고 가짜 `fetchEventSource` 와 목 스트림으로만 확인했다.

4. 실제 낭독기(VoiceOver, NVDA)가 새 알림 안내와 팝오버를 읽는 방식. axe 와 role, aria 속성만 확인했다.
5. 영어 화면은 단위 테스트와 조정자의 크롬 확인으로 봤다(e2e 는 한국어).
6. 좁은 화면(1024px 미만)에서 팝오버가 실제로 화면 안에 남는지. 사이드바가 열려 있지 못해 볼 수 없었다. 1280px 에서 계산된 `max-width` 만 확인했다.
