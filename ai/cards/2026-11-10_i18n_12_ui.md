# i18n 12: @everp/ui 한국어 기본 문구

- 출처: i18n 10 결과 3(packages/ui 한국어 기본 문구)
- 브랜치: feat/i18n\_12\_ui
- 역할 교대 실험 첫 카드. 같은 브리프로 Codex 와 Claude 가 따로 구현한 맞대결(`ai/experiments/2026-11-10_codex_vs_claude.md` 3-2절). Claude 구현(Y)을 골랐고, 리뷰 지적은 Codex 가 고쳤다.

## 결과

1. 패키지에 `UiText` 타입, 한국어 `defaultUiText`, `UiTextProvider`, `useUiText` 를 둔다(`packages/ui/src/UiText.tsx`). 패키지는 next-intl 을 모르고, 앱의 `src/i18n/UiTextBridge.tsx` 가 `IntlProvider` 안에서 `ui` 메시지를 넘긴다. Provider 가 없으면 한국어 기본값이라 Storybook 과 패키지 테스트, `check:lib` 는 그대로다.
2. 패키지 컴포넌트 안 한국어 글자 28개 → 0(기본값 파일 한 곳으로). 쪽 넘김, 표 빈 줄, 드롭다운, 검색 막대, 로딩, 오류, 모달 상태 상자, 충돌 안내, 스파크라인 요약, 공정 목록, 입력 팝업 확인.
3. 영어 총 건수는 "Total {count}"(명사 없이 단복수 문제를 피함). 자릿수 구분은 없다(결정 기록).
4. 테스트: 영어 렌더와 한국어 원문 고정(`src/i18n/uiText.test.tsx`), 패키지 기본값(`UiText.test.tsx`), 운영 빌드 영어(`e2e/i18n.spec.ts` 추가). 컴포넌트만 옛 코드로 되돌리면 영어 테스트가 모두 실패한다.
5. 첫 로드: 화면마다 +0.9~1.1KB(이 카드만). 정적 렌더 유지.
6. 같이 고친 것: `ai/decisions.md` 의 i18n 10 행이 "안 하기로 한 것" 표에 붙어 있었고 범위 표기가 취소선으로 깨져 있었다(#94 의 실수). 본 표로 옮겼다.
7. 남긴 결함(다음 카드 후보): InputList 삭제 버튼과 입력 팝업 연필 버튼에 접근 가능한 이름이 없다. 충돌 설명 조사가 "{subject}을" 로 고정. ModalStatusBox 와 SimplePagination 버튼에 `type="button"` 없음. InputList 에 생산 도메인 글자와 `h1` 이 박혀 있다.
