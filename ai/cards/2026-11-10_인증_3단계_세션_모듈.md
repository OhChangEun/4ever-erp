# 인증 3단계: 세션 처리를 한 모듈 뒤로(SessionStore 경계)

- 출처: 계획 8절 2번(SessionStore), 8번(사용자 타입 위치). OIDC 카드(4단계) 앞의 정리
- 우선순위: 4 유지보수성(OIDC 를 붙일 때 고칠 곳을 한 곳으로), 1 동작 그대로
- 브랜치: refac/인증_3단계_세션_모듈
- 크기: 반나절

## 현상

1. 세션 쿠키를 다섯 곳이 직접 다룬다(페이지 프록시, API 프록시, 로그인, 로그아웃, me). 쿠키 이름, 옵션, 검증 호출이 흩어져 있어 세션 방식을 바꾸면(sid 쿠키 + 서버 저장소) 다섯 곳을 다 고쳐야 한다.
2. 사용자 타입 `userInfoResponse` 와 응답 가드가 옛 OAuth 콜백 폴더(`(public)/callback/`)에 있다. 같은 폴더의 `callback.api.ts` 는 쓰는 곳이 없다.

## 완료 기준

1. `src/server/auth/session/`: `SessionStore` 인터페이스, 데모용 쿠키 저장소(지금 동작: 서명 JWT 쿠키), 모듈 함수 `startSession`, `readSession`, `endSession`(테스트).
2. 다섯 곳이 이 모듈만 쓴다. 쿠키 이름과 옵션은 모듈 안에만 있다.
3. 사용자 타입은 `src/lib/auth/userInfo.ts` 의 `UserInfo`. `callback.api.ts` 삭제.
4. 동작은 그대로(로그인, 권한, 401, e2e 전부 통과).

## 결정

1. 메모리 저장소(sid 쿠키)는 이번에 만들지 않는다. 쓰는 곳이 생기는 OIDC 카드에서 만든다(쓰지 않는 코드를 미리 두지 않는다).
2. 데모 저장소는 상태가 없어 강제 로그아웃(`deleteBySub`)을 못 한다. 인터페이스에는 두고 데모 구현은 아무것도 안 한다고 주석으로 적는다.
