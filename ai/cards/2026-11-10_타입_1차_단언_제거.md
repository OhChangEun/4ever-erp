# 타입 1차: 단언(as), non-null(!), any 제거

- 출처: 계획 4-3절, 블록 4 타입. 린트 `consistent-type-assertions` 104, `no-non-null-assertion` 10, `no-explicit-any` 억제 20
- 우선순위: 1 서버 응답을 믿는 자리 드러내기, 2 실패를 숨기지 않기(단언 뒤의 런타임 오류), 4 유지보수성
- 브랜치: refac/타입_1차_단언_제거
- 크기: 하루

## 현상

1. 단언 104건. 유형: 통계 카드 reduce 초깃값 12, `role as string` 8, `statusCode as string` 6, 드롭다운 상태 `as XStatus` 4 + Dropdown 안 `key as T` 2, 바깥 클릭 `as Node` 6, FormData `as string` 7, 응답 본문 `res.json() as` 3, 모달 열기 3, Input 합성 이벤트 3, InputList 4, 목 핸들러 25, 그 밖 개별 20여 건.
2. non-null 10건. 그중 모달 3곳(고객 상세, 주문 상세, 견적 검토)은 조회 오류 창을 닫으면 `customer!.customerNumber` 에서 화면이 깨진다(TypeError).
3. `Input` 은 `{ ...e.target, value }` 로 새 이벤트를 만들어 단언했다. DOM 속성은 펼쳐지지 않아 받는 쪽의 `e.target.name` 이 undefined 였다.
4. `InputList` 는 키를 제네릭 T 로 받고 `(key as number) + 1` 로 늘렸다. 문자열 키면 "3" + 1 = "31".

## 완료 기준

1. `consistent-type-assertions`, `no-non-null-assertion` 0건, `no-explicit-any` 억제 0건. 두 규칙을 error 로 올린다. 예외는 이유를 적은 한 줄만.
2. 서버 응답과 FormData 는 타입 가드로 읽는다(테스트). 모양이 틀린 세션 응답은 로그인으로 보낸다.
3. 오류 창을 닫은 모달이 깨지지 않는다(테스트).
4. Input 이 다듬은 값을 넘길 때 name 을 잃지 않는다(테스트).
5. 새 경고 없음. 테스트, 빌드, e2e 통과.

## 결정 (AI 가 정함, 사용자 2026-11-10 "끝까지 진행")

1. 모달 열기의 제네릭 단언 1줄은 남긴다. 단언 없이 쓰는 시그니처는 호출부 37곳의 리터럴 타입 추론을 깨뜨린다(시험 파일로 확인).
2. Dropdown 의 "항목 없음" 줄은 값을 '' 로 바꾸지 않고 닫기만 한다. '' 는 상태 유니온 밖의 값이라 필터로 나가면 안 된다.
3. 서버 드롭다운이 코드 목록을 정하는 필터 2곳(MRP 계획 주문 상태, 가용재고 상태)은 state 를 string 으로 둔다.
4. `ApiResponse` 판별 유니온, zod 3도메인, KeyValueItem DTO 분리는 타입 2차 카드로 나눈다.
