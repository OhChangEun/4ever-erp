# effect 로 복사하는 상태 2차 (폼 초기화, 마운트 플래그, 파생 계산)

- 출처: 린트 억제 `react-hooks/set-state-in-effect` 남은 10건(R01, R02), 1차 카드의 후속
- 우선순위: 2 입력 보존(창고 수정 폼), 4 유지보수성
- 브랜치: refac/effect로_복사하는_상태_2차
- 크기: 반나절

## 현상

1. 창고 수정 모달(`ManageWarehouseModal.tsx:104`)이 effect 로 서버 데이터를 폼에 복사한다. 재조회가 새 객체를 주면(다른 사용자가 고친 뒤, 수정 실패의 무효화 뒤) 입력이 덮인다. 프로필 폼에서 고친 것과 같은 종류(우선순위 2).
2. 레이아웃 2곳이 마운트 플래그와 창 크기를 effect 로 state 에 넣는다. Provider 2곳(모달, 토스트)도 포털용 마운트 플래그를 effect 로 켠다.
3. BOM 트리(`BomTreeContainer.tsx:54`)는 props 를 변환한 결과와 로딩, 오류를 effect 로 state 에 넣는다. 변환은 동기라 로딩 상태가 의미 없다.
4. 공급사 폼(`SupplierFormModal.tsx:85`)은 드롭다운 선택값을 effect 로 다른 state 에 옮긴다(같은 값 두 군데, R05).
5. 창고 3D 뷰(`WarehouseVisualizer.tsx:36`, `:55`)는 활성 창고와 선택 품목을 props 와 보기 모드에서 effect 로 맞춘다.
6. 드롭다운 입력(`DropdownInputModal.tsx:32`)은 부모 값을 effect 로 초안 state 에 복사한다.
7. 죽은 setter 전달 2곳: 재고 상세 모달의 `setSelectedItemId`(부모 state 를 아무도 안 읽음, 안 쓰는 변수 경고 1건), 전표 상세 모달의 `setSelectedInvoiceId`(받는 쪽이 안 씀).

## 완료 기준

1. 창고 수정 폼은 데이터가 처음 왔을 때 한 번만 채운다. 재조회가 다른 값을 줘도 입력이 남는다(테스트).
2. 공통 훅 `useMediaQuery`, `useIsClient`(`useSyncExternalStore`). 레이아웃과 Provider 4곳이 쓴다.
3. BOM 트리 변환은 순수 함수 `buildBomTree` + `useMemo`. 변환 실패 문구는 그대로.
4. 공급사 카테고리는 선택 핸들러에서 한 번에 바꾼다. 3D 뷰의 활성 창고와 선택 품목은 계산으로 얻는다. 드롭다운 입력은 열 때 초안을 채운다.
5. 죽은 setter 전달을 지운다.
6. `set-state-in-effect` 억제 10 → 0. 새 경고 없음. 테스트, 빌드, e2e 통과.
