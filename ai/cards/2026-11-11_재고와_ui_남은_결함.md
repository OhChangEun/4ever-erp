# 재고와 ui 남은 결함

- 출처: `2026-11-10_재고_화면_결함.md` 의 "카드 밖에서 발견한 것" 2개, `2026-11-10_ui_버튼_접근성과_충돌_안내_조사.md` 결과 6 의 남긴 문제 2개
- 우선순위: 1 서버와 일치(창고 유형), 2 입력 보존(목록 입력 팝업), 4 유지보수성(메모 중복, 입력칸 이름)
- 브랜치: fix/invui
- 구현: Claude(erp-dev)

## 결정할 것

1. 창고 수정 폼의 RAW 처리와 등록 폼 초기값. AI 결정으로 `ai/decisions.md` 본표에 한 줄 남겼다. RAW, RAW_MATERIAL 은 요청 코드 MATERIAL 로 채우고, 모르는 값은 바꾸지 않고 옵션을 하나 더 둔다. 등록 폼은 고르지 않으면 막는 대신 초기값을 처음 보이는 옵션 MATERIAL 로 둔다. 막으려면 새 안내 문구가 필요하고, 화면은 이미 원자재를 선택한 모습이다.
2. 목록 입력 팝업을 다시 열 때의 값. 열 때 부모의 최신 `initialItems` 로 초안을 채우고, 열려 있는 동안은 부모가 바꿔도 덮지 않는다. `DropdownInputModal` 이 이미 쓰던 방식이라 행으로 남기지 않고 코드 주석에 적었다.

## 근거

- 팀 백엔드 사본 `_4EVER_BE_GW/.../scm/im/dto/WarehouseUpdateRequestDto.java:20` 과 `WarehouseCreateRequestDto.java:20` 이 창고 유형을 MATERIAL, ITEM, ETC 로 적는다. 원자재 요청 코드는 MATERIAL 이다. RAW 는 목 응답(`src/mocks/handlers/warehouse.handlers.ts:49`)에만 있고 응답 enum 은 사본으로 확정할 수 없다.
- 등록 폼(`AddWarehouseModal.tsx`)도 같은 세 값이었다. 두 폼이 `warehouse.constants.ts` 의 목록 하나를 쓰게 했다.
- React 는 controlled select 의 값과 맞는 옵션이 없으면 첫 옵션을 선택해 보인다. 그래서 RAW 창고를 열면 화면은 원자재인데 저장 요청은 RAW 였다.

## 결과

1. 창고 수정. RAW, RAW_MATERIAL 창고를 열면 원자재가 선택돼 보이고, 유형을 건드리지 않고 저장하면 MATERIAL 을 보낸다. 목록에 없는 PRODUCT 같은 값은 그 값의 표시 라벨(완제품창고)로 옵션을 하나 더 두고 그대로 보낸다. 다른 유형을 골랐다가 되돌릴 수 있게 서버 값과 초안 둘 다 남긴다. 테스트 `ManageWarehouseModal.test.tsx` 4건(RAW, RAW_MATERIAL, ITEM, PRODUCT). 수정 전 ITEM 을 뺀 3건이 실패했다(ITEM 은 정상 경로 확인용).
2. 재고 상세 이동 기록의 메모 중복. 참조 번호 줄에 `참조 | 메모` 로 붙이고, 바로 아래 줄에 같은 메모를 또 그렸다. 아래 줄의 `note &&` 조건은 주석 처리돼 있었다(`cb925a1` 부터). 참조 줄은 번호만 보이고, 메모는 있을 때만 아래 줄에 한 번 보인다. 테스트 `inventory.defects.test.tsx` 1건. 수정 전 메모가 2개로 실패했다.
3. `InputList` 입력칸 이름. `UiText.inputList.item(position)` 을 추가했다. 한국어 기본값 `1번 항목`, 영어 `Item 1`. 순번은 키가 아니라 화면에 보이는 번호다. 타입과 기본값(`packages/ui/src/UiText.tsx`), 브리지(`src/i18n/UiTextBridge.tsx`), ko/en `ui` 메시지 네 곳을 같이 고쳤다. 패키지는 next-intl 을 모르는 그대로다. 테스트는 패키지 `InputActions.test.tsx` 1건, 앱 `uiInputActions.test.tsx` ko/en 2건. 수정 전 3건 모두 실패했다.
4. `DropdownInputListModal` 다시 열기. 예전엔 `useState(initialItems)` 첫 값만 써서 부모가 바꾼 목록이 다시 열어도 안 보였다. 열 때 `setItems(initialItems)` 로 초안을 채운다. 연필 버튼 색도 초안이 아니라 부모 값(`initialItems`) 기준으로 바꿔 `DropdownInputModal` 과 맞췄다. 테스트 `DropdownInputListModal.test.tsx` 3건(닫힌 동안 바뀐 값, 확인 뒤 바뀐 값, 열린 동안 입력 보존과 그 값 제출). 수정 전 3건 모두 실패했다. 세 번째는 입력칸 이름이 없어서 실패한 것이고, 입력 보존 자체는 수정 전에도 지켜졌다.
5. `DropdownInputModal` 은 이미 열 때 부모 값으로 채우고 있었다. 열린 동안 입력 보존 테스트를 1건 더했고 수정 전에도 통과했다(보호용).
6. 창고 등록 초기값. 유형 초기값이 빈 문자열이라 화면은 원자재인데 유형을 건드리지 않고 등록하면 빈 값을 보냈다(우선순위 1, 코디네이터 요청으로 이 카드에 포함). 백엔드 사본 `WarehouseCreateRequestDto.java:20` 이 MATERIAL, ITEM, ETC 를 받는다. 초기값을 `DEFAULT_WAREHOUSE_TYPE`(MATERIAL)으로 두고, 옵션은 수정 폼과 같은 `WAREHOUSE_TYPE_OPTIONS` 를 쓴다. 테스트 `AddWarehouseModal.test.tsx` 2건(그대로 등록하면 MATERIAL, 부품을 고르면 ITEM). 수정 전 첫 건이 빈 값으로 실패했다(둘째는 정상 경로 확인용).
7. 화면의 한국어 문구는 새 접근 가능한 이름 말고는 바꾸지 않았다. `ARCHITECTURE.md` 210줄에 입력칸 이름이 같은 경로를 쓴다고 덧붙였다. 앵커 줄 번호(`UiText.tsx:43`, `UiTextBridge.tsx:50`)는 그대로 맞다.

## 남긴 것

1. `InputList` 삭제 버튼 이름은 여전히 모든 줄이 `항목 삭제` 로 같다. 줄을 구분하려면 순번을 넣어야 하지만 기존 테스트와 번역 문구가 바뀌어 별도로 정할 일이다.
2. `ai/decisions.md` 에 행을 더하면서 출처 칸이 넓어져 prettier 가 표 전체 패딩을 다시 맞췄다. 내용 변경은 한 줄이다.
3. SCM_PP 의 실제 창고 유형 enum 과 PUT 검증은 사본에 없어 확인하지 못했다. 목록에 없는 유형(PRODUCT 등)과 빈 값을 수정 때 그대로 보내는 동작이 서버에서 통과하는지는 팀 확인 필요(verified=false).
4. 창고 수정 폼의 유형 라벨 모양이 섞여 있다. 추가 옵션은 재고 라벨(완제품창고), 기본 옵션은 창고 메시지(원자재)다. 맞추면 기존 한국어 문구가 바뀌어 고치지 않았다.
5. 패키지 공개 타입 변경. `UiText.inputList.item` 이 필수 필드라 패키지 밖에서 `UiText` 를 직접 만드는 쪽은 타입이 깨진다. 이 레포에서 직접 만드는 곳은 `src/i18n/UiTextBridge.tsx` 하나고 같이 고쳤다. `defaultUiText` 를 펼쳐 만드는 쪽(패키지 `UiText.test.tsx`)은 영향이 없다.
