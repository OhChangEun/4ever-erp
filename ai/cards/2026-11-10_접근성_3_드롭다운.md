# 접근성 3: Dropdown 키보드와 listbox 의미

- 출처: 계획 10절 결정 2(Dialog, Select, Popover 는 headless), 블록 6 "Dropdown 키보드". 기존 계획의 접근성 문제 2개 중 나머지 하나
- 우선순위: 2(키보드 사용자가 필터와 폼 값을 못 고름), 3(첫 로드 JS), 4
- 브랜치: feat/접근성_3_드롭다운
- 크기: 반나절

## 현상

1. `Dropdown`(`src/app/components/common/Dropdown.tsx`)은 버튼과 `ul > li` 목록이다. 목록 항목은 마우스 클릭만 받는다. 화살표, Enter, Home/End, 글자 입력으로 고를 수 없다.
2. 스크린리더에는 "버튼"과 이름 없는 목록으로 읽힌다. 펼침 여부, 고른 값, 지금 가리킨 항목이 전달되지 않는다.
3. 27개 파일이 쓴다(필터와 모달 폼). 거의 모든 화면의 첫 로드에 들어간다.

## 재현

1. `/purchase` 에서 Tab 으로 필터 드롭다운 버튼에 간다.
2. 아래 화살표를 눌러도 목록이 열리지 않는다. Enter 로 열어도 항목으로 갈 방법이 없다.

## 영향 범위

공통 컴포넌트 `Dropdown` 하나. 쓰는 화면 27파일. 서버 상태와 쿼리 키는 건드리지 않는다.

## 완료 기준

1. 버튼은 `role="combobox"`, 이름은 placeholder, `aria-expanded`, `aria-controls`. 목록은 `role="listbox"`, 항목은 `role="option"` 과 `aria-selected`.
2. 닫힌 상태에서 아래, 위 화살표나 Enter, Space 로 연다. 열리면 고른 항목(없으면 첫 항목)을 가리킨다.
3. 화살표로 옮기고 Home/End 로 처음과 끝, 글자를 치면 그 글자로 시작하는 항목으로 간다. Enter, Space 로 고르고 닫는다. Esc 는 값을 바꾸지 않고 닫는다.
4. 포커스는 버튼에 남고 가리킨 항목은 `aria-activedescendant` 로 알린다(APG select-only combobox).
5. 드롭다운을 연 상태의 axe e2e, 키보드로 필터를 고르는 e2e.
6. 테스트, 빌드, e2e 통과. 첫 로드 JS 증가량을 적는다.

## 남길 수치

`node scripts/measure-bundle.mjs` 로 main 과 브랜치의 첫 로드 JS(gzip).

## 결정 (AI 가 정함)

1. 결정 2 는 Select 도 Radix 로 하자고 했다. 같은 조건에서 따로 잰 크기(esbuild, react 제외, gzip): `@radix-ui/react-select` 32.4KB, 지금 쓰는 `@floating-ui/react` 의 위치 훅 11.1KB, 여기에 interaction 훅(useListNavigation, useTypeahead, useRole, useDismiss, useClick)을 더하면 19.1KB. Dropdown 은 거의 모든 화면 첫 로드에 들어가므로 floating-ui interaction 훅을 쓴다(+8KB). 키보드와 aria 를 손으로 짜지 않는다는 결정 2 의 뜻은 지킨다.
