# React 훅 규칙 억제 정리(refs 5, immutability 5)

- 출처: `eslint-suppressions.json` 의 `react-hooks/refs` 5, `react-hooks/immutability` 5. 블록 4 타입 뒤 정리
- 우선순위: 4 유지보수성(억제가 남으면 같은 규칙의 새 위반이 묻힌다), 1 오류 창 상태
- 브랜치: refac/react_훅_억제_정리
- 크기: 한두 시간

## 현상

1. floating-ui 를 쓰는 5곳(CalendarButton, Dropdown, DropdownInputListModal, DropdownInputModal, 알림 드롭다운)이 JSX 에서 `refs.setReference`, `refs.setFloating` 을 읽는다. React 규칙이 렌더 중 ref 접근으로 본다.
2. 견적 상세, 견적 검토 모달은 오류 창 state 를 선언하기 전에 effect 로 `isError` 를 복사한다.
3. 고객 수정 모달은 렌더 때 만든 `let` 을 저장 핸들러가 다시 대입한다. 3D 자유 시점은 렌더마다 만든 벡터를 프레임 콜백이 바꾼다.

## 완료 기준

1. 두 규칙 억제 10 → 0. 새 경고 없음.
2. 오류 창은 `useDismissibleError` 로 맞춘다(1차 카드와 같은 동작).
3. 테스트, 빌드, e2e 통과.

## 결정

없음. 동작을 바꾸지 않는 정리.

## 결과

1. floating-ui 콜백 ref 는 `const { setReference, setFloating } = refs;` 로 꺼내 JSX 에 넘긴다. 효과 안의 `refs.floating.current` 는 그대로.
2. 견적 모달 2곳은 `useDismissibleError`. 고객 수정 모달은 핸들러 안의 `const`. 3D 자유 시점은 벡터를 ref 에 한 번 만든다.
3. 억제는 `scripts/prepare.js` 의 CommonJS require 1건만 남았다(Node 스크립트라 맞는 억제).
4. ESLint 경고 489 → 488. 단위 180, 빌드, e2e 38 통과.
