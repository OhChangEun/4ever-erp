# 오류 경계 문구 영어

- 출처: AppError 오류 줄 영어 결과 5(오류 경계 3곳의 한국어 고정 문구)
- 우선순위: 2(실패를 숨기지 않는다. 영어 사용자도 무엇이 깨졌고 무엇을 누르면 되는지 읽는다)
- 브랜치: fix/errbound
- 구현: Claude(erp-dev)

## 완료 기준

1. 루트 경계(`src/app/global-error.tsx`): 언어 provider 없이 `NEXT_LOCALE` 쿠키로 ko, en 을 고른다. 네트워크가 끊겨도 동작한다. 클라이언트 컴포넌트 유지.
2. 화면 경계(`src/app/(private)/error.tsx`): `useTranslations` 로 꺼낸다.
3. 모달 경계(`ModalContainer` 안 `@everp/ui` `ErrorBoundary`): 대체 화면이 화면 언어를 따른다. 패키지는 next-intl 을 모른다.
4. 한국어 글자는 예전과 같다. 오류 로그(`console.error`), digest(오류 ID), 다시 시도와 창 닫기 동작은 그대로.
5. (조정자 지시로 추가) 앱 층 경계(`src/app/error.tsx`): next-intl 로 옮기고, `error.message` 를 화면과 복사 내용에 두지 않는다. 원문은 콘솔(오류 보고 자리)에만. 나머지 두 경계도 같은 기준인지 확인한다.

## 결과

1. 루트 경계: 파일 안 작은 표(ko, en 각 4줄)에서 고른다. 언어는 `useSyncExternalStore` 로 쿠키를 읽고, 서버 렌더 값은 한국어다(IntlProvider 와 같은 방식이라 하이드레이션이 어긋나지 않는다). `<html lang>` 도 고른 언어로 바뀐다(예전엔 늘 `ko`). `en.json` 을 import 하지 않은 이유는 결정 기록 "오류 경계 영어" 행.
2. 쿠키 읽는 함수 `readCookieLocale` 을 `IntlProvider.tsx` 안에서 `src/i18n/locale.ts` 로 옮겨 두 곳이 같이 쓴다(같은 파싱을 두 번 쓰지 않게, R22). 동작은 같다.
3. 모달 경계는 이미 영어였다. i18n 10(`d3f5d92`)에서 `ModalContainer` 의 대체 화면이 `modal.renderError`, `modal.closeWindow` 를 쓰게 바뀌었다. 패키지 `ErrorBoundary` 는 글자를 그리지 않고 `fallback` 을 앱에서 받는다. 그래서 `UiText` 는 건드리지 않았다. AppError 카드 결과 5 의 "3곳" 중 이곳은 그 카드 시점에 이미 고쳐져 있었다.
4. 화면 경계: 공통 메시지에 `errorBoundary`(screen, hint, errorId, retry) 를 ko, en 같이 넣었다. 한국어 출력은 글자 하나까지 같다(테스트 2번째가 전체 글자를 본다).
5. 첫 로드 JS(gzip, KB). `pnpm build` 뒤 `node scripts/measure-bundle.mjs`. 고치기 전은 같은 작업 트리를 stash 하고 빌드해 쟀다.

   | 라우트      | 전    | 후    |
   | ----------- | ----- | ----- |
   | /production | 309.3 | 309.3 |
   | /dashboard  | 258.4 | 258.5 |
   | /warehouse  | 241.5 | 241.6 |
   | /login      | 186.4 | 186.6 |
   | /           | 166.1 | 166.1 |

   후는 리뷰 반영까지 끝난 트리에서 다시 잰 값이다. 화면별 +0.0에서 0.2, ko.json 공통 메시지(errorBoundary 키) 증가 포함. 루트 경계 청크는 모든 화면에 실린다(빌드된 HTML 에서 확인). `en.json` 을 넣었다면 gzip 3.6KB 가 더 붙는다.

6. 확인(5번 항목 전): `pnpm exec tsc --noEmit -p .` 통과, `pnpm exec eslint .` 0 errors 0 warnings, `pnpm exec vitest run` 102 파일 664 통과, `pnpm --filter @everp/ui test` 66 통과, `pnpm --filter @everp/ui build` 통과, `pnpm --filter @everp/ui check:lib` 통과, `pnpm build` 통과.
7. 앱 층 경계(`src/app/error.tsx`): 루트 레이아웃의 IntlProvider 안이라 `useTranslations('errorBoundary')` 를 쓴다(title, unknown, home, copy, copyLabel, copied, copyFailed 를 ko, en 같이 추가. retry, errorId 는 화면 경계와 같이 쓴다). 한국어 글자는 예전과 같다. 다만 앱 층 경계의 안내 줄과 복사 내용은 결과 8 대로 바뀌었다.
8. 내부 문구 숨김: 예전엔 안내 줄에 `error.message` 를 그대로 보였고(예: `Cannot read properties of undefined ...`) 복사 내용 앞에도 붙였다. 이제 안내 줄은 늘 "알 수 없는 오류가 발생했습니다." 이고, 운영의 복사 내용은 "오류 ID {digest}" 한 줄이다. 원문은 `console.error('[AppError]', error)` 에만 남는다. 개발 모드는 원인 문구와 stack 을 보이고 복사한다(리뷰 반영 3). 개발자 자기 화면이라 원인을 바로 봐야 해서다(주석에 적었다). `(private)/error.tsx` 와 `global-error.tsx` 는 원래 `error.message` 를 그리지 않는다(화면 경계는 개발 모드에서만 stack). 고칠 것 없음.
9. 7절 체크리스트 8개: 새 state 와 effect 없음(언어는 쿠키에서 바로 읽는다), 쿠키 파싱 출처 하나, `as`, `!`, `any`, eslint-disable 없음, 기존 테스트 기대값 유지.

## 남긴 것

1. 루트 경계의 글자 4줄은 메시지 파일 밖이라 `src/i18n/messages.test.ts` 의 키 비교에 안 걸린다. 타입 `Record<Locale, ...>` 가 두 언어를 다 요구하는 것으로 대신한다.
2. 루트 경계가 떠 있는 동안 언어를 바꾸는 곳이 없어 쿠키 변경을 구독하지 않는다.
3. e2e 는 돌리지 않았다. e2e 와 다른 소스에 세 경계의 글자를 찾는 곳이 없다(grep).
4. `(private)/error.tsx` 도 개발 모드에서 `error.stack` 만 보여, Safari 와 Firefox 에서는 원인 문구가 빠진다. 리뷰 3 은 앱 층 경계만 짚어 손대지 않았다. 고치려면 `devDetail` 을 같이 쓰면 된다.
