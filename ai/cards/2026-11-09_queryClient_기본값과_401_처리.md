# queryClient 기본값과 401 처리

- 출처: 아키텍처 계획 5절 6번(캐시 기본값), 결정 6과 8 / 오류 분리 카드의 잔여 3건
- 우선순위: 1 서버와 일치 (포커스 refetch, 401 즉시 로그아웃), 2 실패 노출 (retry 는 네트워크와 5xx 만)
- 브랜치: refac/queryClient_기본값과_401_처리
- 크기: 1일

## 현상

1. QueryClient 두 개(서버 `src/lib/queryClient.ts:4`, 클라이언트 `src/app/providers.tsx:17`) 모두 기본 옵션이 없다. TanStack Query 기본값은 `staleTime 0`, `retry 3`(모든 오류에), `gcTime 5분`, `refetchOnWindowFocus true`.
2. 그래서 404 나 403 도 3번 재시도한다. 실패가 화면에 보이기까지 1 + 2 + 4 = 7초가 걸린다. 오류 분리 카드 뒤로 실패가 보이게 됐는데 7초 뒤에 보인다.
3. 목록 20곳이 `staleTime: 1000` 을 각자 적어 두었다(`grep -rn "staleTime: 1000" src` 20건). 탭을 1초 안에 오가면 캐시, 넘으면 재요청. 기준이 코드 곳곳에 흩어져 있다.
4. API 가 401 을 돌려줘도(세션 만료, `src/app/api/proxy/[...path]/route.ts:64`) 화면은 오류 상자만 보여준다. 로그인으로 보내는 곳은 페이지 진입 때의 `_PrivateGuard` 뿐이다(`src/app/(private)/_PrivateGuard.tsx:23`). 열어 둔 탭에서 세션이 만료되면 모든 목록이 "로그인이 필요합니다" 오류로 바뀌고 사용자는 직접 새로고침해야 한다.
5. 오류 분리 카드 잔여: `fetchProductionStats` 의 `catch → null` (`src/app/(private)/production/api/production.api.ts:37`)과 그걸 우회하는 `ProductionClient.tsx:21`, `'axios'` 직접 import 2곳(`inventory.api.ts:2`, `production.api.ts`). 린트 1차 브랜치가 머지돼 이제 건드릴 수 있다.

## 재현

1. MSW 켜고 구매 발주 목록에서 요청 헤더 `x-mock-scenario: 404`. DevTools 네트워크에 같은 요청이 4번 찍히고 7초 뒤 오류 상자.
2. `x-mock-scenario: 401`. 오류 상자 "로그인이 필요합니다"만 보이고 로그인 페이지로 가지 않는다.

## 영향 범위

- 모든 `useQuery`(41곳)와 `useMutation`(36곳). 키는 바뀌지 않는다.
- 서버 prefetch 4 페이지(`dashboard`, `hrm`, `inventory`, `production` 의 `page.tsx`)가 같은 `getQueryClient` 를 쓴다. 서버에서는 재시도하면 안 된다(렌더가 멈춘다).
- 인증 경로: 401 → `authStore` 비우고 `/login?returnTo=<현재 경로>`. `_PrivateGuard` 와 같은 규칙.
- 드롭다운 기준 데이터의 `staleTime: Infinity` 는 유지한다(`useDropdown.tsx:18`, 인사 모달 4곳).

## 완료 기준

1. 두 QueryClient 가 한 팩토리(`createQueryClient`)에서 나온다. 기본값: `staleTime 30초`, `gcTime 5분`, `refetchOnWindowFocus true`, retry 는 `AppError.kind` 가 `network` 또는 `server` 일 때만 2회, 그 외 0회. 서버용은 retry 0회.
2. 401(`kind === 'unauthorized'`)이 쿼리나 mutation 에서 나오면 한 곳(QueryCache, MutationCache `onError`)에서 `authStore` 를 비우고 `/login?returnTo=<pathname>` 으로 보낸다. 여러 쿼리가 동시에 401 이어도 한 번만 보낸다.
3. `staleTime: 1000` 20곳을 지워 기본값을 따른다. `Infinity` 5곳은 그대로.
4. `fetchProductionStats` 가 실패를 reject 한다. `ProductionClient` 의 null 우회 코드가 사라진다. `'axios'` 직접 import 0건(`no-restricted-imports` 0건).
5. 기존 테스트 54개와 새 테스트 통과. `npm run build` 통과. 린트 경고가 739 를 넘지 않는다.

## 결정 질문 (게이트 1)

결정 6과 8 이 이미 있다. 추가로 AI 가 정한 것(사용자 "더 안 건드린다"):

1. timeout 은 재시도하지 않는다. 결정 6 이 "네트워크와 5xx" 라고 했고, 타임아웃 재시도는 4초 × 3 = 12초를 기다리게 한다.
2. 401 이동은 `window.location.assign` 으로 전체 새로고침. 라우터가 없는 곳(QueryCache)이고, 세션 만료 뒤엔 캐시를 다 버리는 게 맞다.
3. 결정 8 의 "폼 초안 sessionStorage 보존"은 react-hook-form 카드(결정 21)로 넘긴다. 폼 상태가 아직 컴포넌트마다 달라 공통으로 저장할 자리가 없다.
4. 서버 QueryClient 는 retry 0. 서버 prefetch 가 실패하면 클라이언트가 다시 가져온다.
