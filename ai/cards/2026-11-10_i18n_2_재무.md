# i18n 2: 도메인별 메시지와 재무 화면

- 출처: i18n 1 결정 3(도메인 문구는 도메인마다), 마무리 문서 다음 카드 1번
- 우선순위: 3(문구가 늘어도 모든 화면 첫 로드가 늘지 않는다), 4
- 브랜치: feat/i18n\_2\_재무

## 완료 기준

1. 도메인 메시지 구조: `src/i18n/messages/{도메인}/{ko,en}.json`, 도메인 레이아웃의 `DomainMessages` 가 공통 메시지에 합쳐 넘긴다. 한국어는 그 화면 청크에만, 다른 언어는 고를 때만 받는다.
2. 도메인 폴더도 precompile(플러그인 `messages.path` 목록). 키 타입과 ko/en 키 일치 테스트를 도메인까지.
3. 재무 화면 문구 전부(탭, 목록, 전표 상세, 재무 현황 차트와 표).
4. 한국어는 예전과 같다(기존 테스트와 e2e 그대로 통과). 운영 빌드에서 영어 전환 e2e.

## 결정 (AI 가 정함)

1. 도메인 메시지 provider 는 `RouteProviders`(모달 provider 포함) 바깥에 둔다. 모달은 거기서 그려져, 안쪽에 두면 모달이 도메인 메시지를 못 본다.
2. 계산 함수(`agingSummary`)는 한국어 이름을 돌려주지 않는다. 화면이 구간 키로 번역한다.
3. 전표 상세 모달의 "고객 상세 데이터" 문구는 복사 실수라 "전표 상세 정보"로 고쳤다.

## 결과

1. `DomainMessages`, `FinanceMessages`, 재무 메시지 키 81개. 상수와 헬퍼는 메시지 키를 들고 그릴 때 번역한다(통계 카드 제목도 캐시에 키로 둬서 언어를 바꿔도 다시 받지 않는다).
2. 한국어 문자열 2,123 → 2,015(재무 107 → 0).
3. 첫 로드 JS: 재무 +1.7KB, 나머지 그대로. 재무는 정적 렌더(○) 유지.
4. 확인: verify(앱 421), build, e2e 73 통과 2 skip, 운영 빌드에서 영어 전환 e2e 3개, 리뷰 지적 없음.
5. 구현: 기반은 메인 세션, 재무 문구 이동은 erp-dev 에이전트.
6. 다음 도메인: 같은 방식으로 생산(329), 영업(318), 인사(312), 재고(222), 구매(205), 대시보드(171), 창고(127). 도메인마다 `next.config.ts` 의 precompile 경로, `global.d.ts` 의 타입, `messages.test.ts` 의 쌍에 한 줄씩 더한다.
