# SSO 포털 2: apps/portal 과 Keycloak SSO, 백채널 로그아웃

- 출처: 계획 16-1 "SSO 두 번째 클라이언트: apps/portal(공급사와 고객사용 얇은 포털, 화면 2개), 같은 realm 으로 SSO, 백채널 로그아웃이 둘 다 끊는다", 결정 29
- 우선순위: 1(로그아웃이 두 앱 모두에서 실제로 세션을 끝낸다), 2(포털 밖 역할은 숨기지 않고 거절을 알린다)
- 브랜치: feat/SSO\_2\_포털
- 크기: 하루

## 완료 기준

1. `apps/portal`(Next 16, 3300): 홈, 주문(공급사는 받은 발주, 고객사는 내 주문), 로그아웃 화면. 인증은 `@everp/auth`.
2. Keycloak 클라이언트 `everp-portal`(realm 파일 + 떠 있는 Keycloak 에 반영하는 `sync-clients.mjs`).
3. e2e(실제 Keycloak): erp 로그인 뒤 포털이 폼 없이 열린다, erp 로그아웃이 포털 세션을 끝낸다, 포털 로그아웃이 erp 세션을 끝낸다, 재무 관리자는 거절된다.
4. CI 가 포털 빌드를 돌린다(e2e 는 Keycloak 이 없어 로컬만).

## 결정 (AI 가 정함)

1. 포털은 배포하지 않는다. 메모리 세션 저장소는 인스턴스 하나에서만 맞고(결정 9), Vercel 에 Keycloak 이 없다.
2. 포털 화면은 Tailwind 없이 CSS 하나. 색은 토큰 값을 옮겨 적었다. 화면 두 개에 빌드 도구를 늘리지 않는다.
3. 포털 데이터는 서버 고정 값. erp 서버 목(MSW)을 포털에 붙이지 않는다.

## 결과

1. 포털 파일 26개(라우트 5, 화면 3, 어댑터), 테스트 11개(역할, returnTo).
2. OIDC e2e 9개 통과(기존 5 + SSO 4), 세 번 돌려 흔들림 없음.
3. 찾아서 고친 erp 결함 둘(같은 PR, 리뷰 파일 참고):
   - 로그아웃 POST 뒤 진행 중이던 다른 요청이 401 을 받으면 전역 처리기가 `/login` 이동을 걸어, 막 시작한 Keycloak 로그아웃 이동을 끊었다. 끊기는 시점에 따라 Keycloak 세션이 남아 로그아웃 뒤에도 포털(과 erp 재로그인)이 폼 없이 열렸다. 로그아웃을 `logout()` 한 곳으로 모으고 떠나는 동안 401 이동을 막았다.
   - `safeReturnTo` 가 앞 글자만 봐서 `/\t/evil.com`, `/a/..//evil.com` 이 외부 주소로 풀렸다(로그인 뒤 열린 리다이렉트). 실제로 풀어 출처와 결과 경로를 확인한다. 포털도 같은 규칙.
4. 남은 것: 포털 데이터는 고정 값(verified=false). 포털 화면의 접근성 axe 점검은 하지 않았다.
