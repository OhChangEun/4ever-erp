# 성능 4: framer-motion 을 CSS 애니메이션으로

- 출처: 기준선(ARCHITECTURE.md 8-1)의 "framer-motion 70.5KB 를 거의 모든 화면이 받는다"
- 우선순위: 3 빠르게 느껴진다, 2 실패를 숨기지 않는다(토스트를 스크린리더가 못 읽음)
- 브랜치: refac/성능_4_애니메이션_CSS
- 크기: 반나절

## 현상

1. framer-motion 은 세 곳(토스트, 모달 틀, 고객사 프로필 모달)에서 페이드와 살짝 움직이는 효과에만 쓴다. 토스트와 모달 틀이 모든 화면에 있어 모든 화면이 70.5KB(gzip)를 받는다.
2. 모달 틀과 프로필 모달은 `AnimatePresence` 가 사라지는 요소 안쪽에 있어 닫힘 애니메이션이 한 번도 재생되지 않았다. 실제로 쓰인 건 등장 효과와 토스트의 사라짐뿐이다.
3. `animate-fadeIn` 클래스를 세 곳(달력, 드롭다운 입력 2곳)에서 쓰지만 정의가 없어 효과가 없다.
4. 토스트에 알림 영역(role=status)이 없어 스크린리더가 읽지 않고, 닫기 버튼에 이름이 없다.

## 완료 기준

1. 전역 CSS 에 키프레임 4개(fade-in, pop-in, toast-in, toast-out). `animate-fadeIn` 도 이때 실제로 동작한다. 움직임 줄이기 설정은 기존 전역 규칙이 따른다.
2. 토스트: 등장과 사라짐을 CSS 로. 사라지는 200ms 동안 DOM 에 남았다가 지운다. role=status, 닫기 버튼 이름(테스트).
3. 모달 틀과 프로필 모달은 등장 효과만 CSS 로(지금도 닫힘 효과가 없다).
4. `framer-motion` 의존성 제거. 첫 로드 JS 전후. 테스트, 빌드, e2e 통과.

## 결정 (AI 가 정함)

1. 토스트 목록이 늘고 줄 때 다른 토스트가 부드럽게 자리를 옮기던 효과(`layout`)는 없앤다. 70KB 를 모든 화면이 받을 만한 효과가 아니다.
