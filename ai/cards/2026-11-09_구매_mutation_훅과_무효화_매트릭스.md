# 구매 mutation 훅과 무효화 매트릭스

- 출처: 아키텍처 계획 5절 1번(무효화 매트릭스), 리팩토링 15문제 표 "mutation 훅 통일" (36곳 중 구매 8곳이 첫 도메인)
- 우선순위: 1 서버와 일치 (mutation 뒤 무효화 범위가 코드 한 곳에 있고 테스트가 지킨다)
- 브랜치: refac/구매_mutation_훅과_무효화_매트릭스
- 크기: 1일. 나머지 도메인(인사 9, 생산 6, 재고 4, 영업 3, 재무 1, 창고 1, 프로필 3, 헤더 1)은 같은 틀로 도메인별 카드

## 현상

1. 구매 도메인의 `useMutation` 8곳이 컴포넌트 안에 있다(`PurchaseOrderListTab.tsx:83`, `:97`, `:111`, `PurchaseRequestListTab.tsx:89`, `:103`, `PurchaseRequestFormModal.tsx:38`, `SupplierFormModal.tsx:93`, `:103`). 무효화할 키 목록이 각 `onSuccess` 안에 복사돼 있다. 발주 승인, 반려, 배송 시작이 같은 3줄을 세 번 적는다.
2. 어떤 mutation 이 어떤 쿼리를 갱신하는지 한눈에 볼 표가 없다. 10월에 잡힌 버그 두 건(통계 카드 누락, 다른 도메인 무효화)이 이 때문이었다. 지금 구매는 통계 키를 다 넣고 있지만 "다 넣었는지"를 확인하는 테스트가 없다.
3. 버그: `rejectPurchaseOrder` 의 URL 끝에 쉼표가 붙는다 (`purchase.api.ts:121` `` `${...REJECT(id)},` ``). MSW 핸들러는 정규식으로 `reject,?$` 를 받아 가려졌고(`purchase.handlers.ts:108`), 서버 목은 못 받아 데모에서 발주 반려가 404 다.

## 재현

1. 구매 > 발주 목록에서 반려. MSW 켠 로컬은 성공, Vercel 데모(서버 목)는 "반려 중 오류" 토스트.
2. 무효화 범위 확인은 지금 방법이 없다. DevTools 의 React Query 패널에서 승인 뒤 어떤 키가 `invalidated` 로 바뀌는지 눈으로 봐야 한다.

## 영향 범위

- 도메인: 구매만. 쿼리 키: `purchaseOrderKeys`, `purchaseRequestKeys`, `supplierKeys`, `purchaseStatsKeys` (`purchase.keys.ts`). 다른 도메인 키는 건드리지 않는다. 재고 쪽에 "재고에서 구매 요청"(`createStockPurchaseRequest`)이 있지만 그건 재고 카드에서.
- 공통 컴포넌트 없음. 토스트와 confirm 은 컴포넌트에 남는다(UI 는 훅이 모른다).
- 인증 경로 없음.

## 완료 기준

1. `src/app/(private)/purchase/api/purchase.mutations.ts` 에 훅 8개가 있고, 컴포넌트 안 `useMutation` 직접 호출이 구매 도메인에서 0건이다.
2. 같은 파일의 `PURCHASE_MUTATION_EFFECTS` 가 "mutation → 무효화 키" 매트릭스를 코드로 가진다. 훅은 이 표를 읽어 무효화한다(표와 동작이 따로 놀 수 없다).
3. 훅마다 테스트: MSW 로 성공시킨 뒤 매트릭스의 키는 `getQueryState(key).isInvalidated === true`, 다른 도메인 키(`['sales', ...]`)와 같은 도메인의 무관한 키(예: 발주 승인 뒤 공급사 목록)는 `false`.
4. 발주 반려 URL 에 쉼표가 없다. MSW 핸들러 정규식도 쉼표를 안 받는다. 테스트가 정확한 경로로 요청하는지 확인한다.
5. `ARCHITECTURE.md` 5절에 매트릭스 표가 있다(코드 표를 옮긴 것).
6. 기존 테스트 70개 통과, 린트 경고 738 이하, build 통과.

## 결정 질문 (게이트 1)

AI 가 정했다(사용자 "더 안 건드린다").

1. 훅은 `UseMutationResult` 를 그대로 돌려주고, 옵션으로 `onSuccess`, `onError` 만 받는다. 토스트, confirm, 모달 닫기는 컴포넌트에 남긴다. 훅이 UI 를 알면 다른 화면에서 못 쓴다.
2. 무효화는 `onSuccess` 가 아니라 `onSettled` 가 아닌 `onSuccess` 에서 한다. 실패했으면 서버가 안 바뀌었으니 다시 가져올 이유가 없다(기존과 같음).
3. 반려 사유(`body`)는 지금처럼 빈 문자열을 보낸다. 사유 입력 UI 는 별도 기능 카드.
4. `mutationKey` 를 매트릭스 이름으로 붙인다(`['purchase', 'approveOrder']`). 다음 카드 "중복 제출 방지"가 `useIsMutating({ mutationKey })` 로 쓴다.
