# Playwright 브라우저 검증

- 출처: 결정 22(Playwright 도입), 사용자 지시 2026-11-10 "크롬 플러그인 왜 끊겼는지 확인하고 다시 진행해줘"
- 우선순위: 2 실패 노출(오류 상태가 실제 화면에서 보이는지), 1 서버와 일치
- 브랜치: chore/playwright_브라우저_검증
- 크기: 반나절

## 현상

1. 지난 카드 7장의 5단계(브라우저 확인)가 전부 미완이다. 크롬 플러그인(claude-in-chrome) 도구가 세션 중간에 사라졌다.
2. 원인: 이 세션은 2026-11-09 21:54 에 Orca 가 `claude --resume=91eee701… --output-format stream-json …` 으로 다시 띄운 프로세스다(pid 57002). 실행 인자에 `--chrome` 이 없다. 크롬 MCP 로그(`~/Library/Caches/claude-cli-nodejs/-Users-oh-chang-eun-dev-4ever-erp/mcp-logs-claude-in-chrome/`)가 2026-11-09T09:00Z(18:00) 세션 시작분까지만 있고, 같은 프로젝트의 다른 MCP(atlassian) 로그에는 12:54Z, 14:52Z 재시작분이 있다. 즉 재시작한 프로세스에서 크롬 MCP 서버가 시작되지 않았다. 홈 디렉터리에서 터미널로 띄운 세션들은 같은 시간대에도 크롬 MCP 가 시작됐다. 확장 프로그램, 네이티브 호스트(`~/.claude/chrome/chrome-native-host`), Chrome 프로세스는 정상이다.
3. 세션 안에서는 다시 붙일 방법이 없다. 사람이 `claude --resume <세션> --chrome` 으로 띄우거나 Orca 의 실행 인자에 `--chrome` 을 넣어야 한다.

## 결정

크롬 플러그인이 붙기를 기다리지 않고 Playwright 로 이 맥에 설치된 Google Chrome 을 직접 띄운다(`channel: 'chrome'`, 브라우저 다운로드 없음). 눈으로 한 번 보고 끝나는 확인 대신 다시 돌릴 수 있는 테스트로 남는다(결정 22 의 "검증 단계의 즉석 확인을 e2e 로 영구화").

## 완료 기준

1. `npm run e2e` 가 `next dev`(3100 포트, 서버 목)를 띄우고 로그인 화면을 거쳐 관리자 세션을 저장한 뒤 테스트를 돈다.
2. 오류 분리 카드의 미완 브라우저 확인: 목록 3화면(구매 발주, 구매 요청, 인사 직원) × 실패 7종에서 화면 문구와 오류 종류 문구가 보이고 빈 목록 문구는 안 보인다(타임아웃은 발주 목록 한 곳).
3. 401 이면 로그인 화면으로 가고 `returnTo` 에 원래 경로가 담긴다.
4. 통계 띠 9 페이지가 통계 500 이면 "지표를 불러오지 못했습니다" 한 줄을 보이고 지표 값(`dd`)이 없다.
5. BOM 상태 변경이 409 면 충돌 다이얼로그가 뜨고 "최신 데이터 불러오기"가 상세를 다시 가져온다.
6. lint, type-check, vitest 그대로 통과.

## 별도 보고

- 대시보드 워크플로 탭 이름이 둘 다 "알 수 없는 프로세스"로 나온다(스크린샷 확인). 서버 목 데이터와 탭 이름 매핑 문제. 대시보드 카드.
- CI 연결은 아직 안 했다. 결정 22 는 Vercel preview 대상인데 preview 는 Vercel 인증 보호가 걸려 있다(배포 URL 직접 접근 401). CI 에서 `next dev` + `npx playwright install chromium` 으로 돌릴지, preview 우회 토큰을 쓸지 다음 카드에서.
- 처음 쓴 테스트에서 빈 목록 문구 두 개를 실제와 다르게 적어 "빈 상태가 안 보인다" 확인이 무의미했다. 실제 문구로 고쳤다.
