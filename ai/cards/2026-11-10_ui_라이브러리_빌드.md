# @everp/ui 라이브러리 빌드와 tree-shaking 확인

- 출처: 계획 16-1 "라이브러리 빌드 툴체인: packages/ui 를 tsup 또는 Vite lib mode 로 ESM 빌드, exports 맵, sideEffects, tree-shaking 확인"
- 우선순위: 4(다음 사람이 패키지를 따로 쓸 수 있다), 3(쓰는 쪽 번들이 안 쓰는 컴포넌트를 받지 않는다)
- 브랜치: chore/ui\_라이브러리\_빌드
- 크기: 반나절

## 완료 기준

1. `pnpm --filter @everp/ui build` 가 `dist/` 에 ESM(파일마다 하나), d.ts, 토큰 CSS 를 만든다. 스토리와 테스트는 빠진다.
2. 의존(react, react-dom, react/jsx-runtime, floating-ui)은 번들하지 않는다.
3. `pnpm pack` 하면 exports 가 dist 를 가리킨다(`publishConfig.exports`). 앱은 지금처럼 소스를 쓴다.
4. `check:lib`: Button 하나만 가져와 번들하면 Sparkline, Table, Dropdown 코드가 없다. `pnpm verify` 에 넣는다.

## 결정 (AI 가 정함)

1. tsup 대신 Vite 라이브러리 모드. Vite 는 Storybook 때문에 이미 있다. 새 의존성이 없다.
2. 앱은 소스를 그대로 쓴다(Turborepo 의 Just-in-Time 패키지). dist 를 쓰게 하면 ui 를 고칠 때마다 빌드를 다시 돌려야 하고 HMR 이 끊긴다. 빌드는 밖에 낼 때의 모양을 지키는 용도.
3. preserveModules. 한 파일로 묶으면 쓰는 쪽이 tree-shaking 을 못 할 때(예: sideEffects 를 안 보는 번들러) 전부 받는다.

## 결과

1. `packages/ui/vite.lib.config.mts`, `tsconfig.build.json`, `scripts/check-lib.mjs`, 스크립트 `build`, `check:lib`. turbo 에 `build`(outputs dist)와 `check:lib`(build 뒤).
2. dist 376KB(소스맵 포함). Button 하나만 가져온 번들 1.7KB(압축 전), 다른 컴포넌트 표식 없음, react/jsx-runtime 은 import 로 남음.
3. `pnpm pack` 결과물: exports 가 `./dist/index.js` 와 `./dist/types/index.d.ts`, 파일은 dist 와 package.json 만.
