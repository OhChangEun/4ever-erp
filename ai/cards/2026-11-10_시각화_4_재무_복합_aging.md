# 시각화 4: 재무 월별 복합 차트와 미수금 aging

- 출처: 계획 17-1 "재무: 월별 매출, 매입, 순이익 복합(막대 + 선), 미수금 aging 막대(30, 60, 90일)", 17-2 규칙
- 우선순위: 1(전표를 처리하면 현황도 다시 받는다), 2(기한 지난 미수금을 숨기지 않는다), 3(차트는 탭을 열 때만)
- 브랜치: feat/시각화\_4\_재무\_복합\_aging
- 크기: 반나절

## 현상

재무 화면에는 기간별 합계(통계 띠)와 전표 목록뿐이다. 달마다 매출과 매입이 어떻게 움직였는지, 받지 못한 돈이 기한을 얼마나 넘겼는지는 전표를 하나씩 열어야 안다.

## 완료 기준

1. 계약에 `GET /business/fcm/analytics/monthly`(최근 12개월, 달마다 매출, 매입, 순이익)와 `GET /business/fcm/analytics/ar-aging`(기준일, 구간 5개: 기한 전, 1~~30일, 31~~60일, 61~90일, 90일 초과. 구간마다 금액과 건수). 목은 openapi-msw.
2. 재무 화면에 "재무 현황" 탭(ALL_ADMIN, FCM 역할만). 왼쪽 월별 복합 차트: 매출, 매입 막대 + 순이익 선(Recharts `ComposedChart`, `next/dynamic`). 금액 축은 억, 만 단위로 줄여 쓴다.
3. 차트 요약 문장(12개월 매출, 매입, 순이익 합계, 순이익이 가장 큰 달과 가장 작은 달, 적자 달 수)을 차트 설명으로 잇고, "표로 보기"가 같은 데이터의 표(12행)를 연다.
4. 오른쪽 미수금 aging: 구간마다 금액, 건수, 비율 막대가 있는 표. 위에 "미수금 ₩X 중 기한 지난 금액 ₩Y(N%)" 문장.
5. 쿼리 키 `financeAnalyticsKeys`(재무 아래). 전표 처리(수금, 지급 요청, 지급 완료)는 통계와 같이 현황도 무효화한다(매트릭스 테스트). 다른 도메인 키는 그대로.
6. 첫 로드 JS 예산 안(Recharts 는 탭을 열 때만). 로딩, 오류(TableStatusBox), 빈 데이터 처리.

## 결정 (AI 가 정함)

1. 탭은 사내 재무 역할(ALL_ADMIN, FCM_USER, FCM_ADMIN)만. 회사 전체 손익이라 영업, 구매 역할과 고객사, 공급사에는 숨긴다. 탭은 맨 뒤에 둬서 기본 탭(매출 전표)은 그대로.
2. 무효화는 통계 띠 규칙을 따른다. 지금 전표 처리가 통계를 무효화하므로 현황도 같이. 서버가 발생 기준인지 현금 기준인지 모르니 넓게 잡는다(같은 도메인 안, 요청 두 개).
3. aging 은 Recharts 막대 대신 표 + CSS 막대. 표가 곧 차트라 "표로 보기"가 필요 없고, 라이브러리 비용도 없다. 막대 색은 하나(구간 이름이 이미 위험도를 말한다, 허용 차트 3번).
4. 색: 매출 blue-500, 매입 gray-300, 순이익 선 gray-900. 범례는 제목 줄의 글자 표시 하나.
