## Codex 가 확인했고 문제 없다고 한 것

1. 모달 하나만 뜬 일반 경로에서는 행 버튼 잠금, 기존 무효화 표, 409 처리가 그대로다.
2. `mutateAsync` 의 reject 는 `ConfirmModal` 의 `try/catch` 가 받는다. unhandled rejection 으로 새지 않는다.
3. 닫기는 id 로 지운다. 이미 닫힌 모달의 `onClose` 가 다시 불려도 다른 모달을 닫지 않는다.
4. 사유 trim, 본문 전달(`comment`, `reason`), 실패 시 입력 보존.
5. textarea 의 Enter 는 제출이 아니다(form 이 없다).
6. 제목(dialog 이름), label 연결, 설명(`aria-describedby`) 연결.
7. 요청 중 Esc 와 X 는 열려 있고(카드 별도 보고 8 의 의도), 바깥 클릭은 막힌다.

확인만 하고 문제 없던 것:

1. 반려 뒤 갱신. `rejectOrder` 는 발주 목록, 상세, 구매 통계(`purchase.mutations.ts:43-47`), `rejectRequest` 는 요청 목록, 상세, 구매 통계(60-64), `rejectLeave` 는 휴가 목록, 근태 목록, 근태 요약(`hrm.mutations.ts:54-58`)을 무효화한다. `mutate` 를 `mutateAsync` 로 바꿔도 `useMutation` 옵션의 `onSuccess`, `onError`, 409 무효화는 그대로 돈다.
2. 본문 키. `purchase.api.ts:72` 가 `{ comment }`, `:123` 이 `{ reason }` 으로 보낸다. 휴가 반려(`hrm.api.ts:184-187`)는 본문이 없다.
3. 급여 성공 순서. 훅 `onSuccess` 가 무효화를 기다린 뒤 급여 모달을 닫고, 그 다음 `mutateAsync` 가 resolve 되어 확인 모달이 자기 id 로 닫힌다. 확인 모달은 급여 모달의 자식이 아니라 스택의 옆 칸이라 부모가 사라져도 남아서 스스로 닫는다. 실패하면 `onError` 토스트 뒤 확인 모달이 열린 채 풀린다.
4. 닫힌 뒤 Promise 가 끝나는 경우. `onClose` 는 `filter` 라 없는 id 면 아무 일도 없고, `setPending(false)` 는 unmount 뒤라 무시된다.
5. 버튼 잠금. `Button` 은 `disabled={props.disabled || loading}`(`packages/ui/src/Button.tsx:48`)이라 `loading={pending}` 인 확인 버튼도 실제로 disabled 다.
6. 빈 catch(`ConfirmModal.tsx:38`). 8곳 호출부의 훅에 전부 `onError` 토스트가 있어 실패가 숨지 않는다. 새 호출부가 `onError` 없는 함수를 넘기면 조용히 풀리기만 한다는 점은 주석에 적혀 있다.
