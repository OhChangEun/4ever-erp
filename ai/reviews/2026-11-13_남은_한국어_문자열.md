## 특히 볼 것 여섯 항목 (진행자 확인)

1. `useOptionLabels`(`src/app/hooks/useOptionLabels.ts:13-19`). 문제 없음.
   - 보내는 key: `options.map(({ key, value }) => ({ key, value: ... }))` 라 key 는 그대로다. 열한 곳 모두 `items`/`options` prop 에만 감쌌고 `value`, `onChange` 는 손대지 않았다. 필터 state(`selectedMesStatus` 등)는 `Dropdown` 의 `onChange(item.key)` 로만 바뀌고 쿼리 키와 요청 파라미터는 그 state 를 쓴다.
   - 바뀐 한국어 글자 둘: '충분', '대기' 를 비교하는 코드는 `src/app` 에 없다(grep 0, 남은 히트는 목과 메시지 파일). MRP 의 `SUFFICIENT` 는 `status.SUFFICIENT`(충족), MES 의 `WAITING` 은 `production.mes.status.WAITING`(대기중)으로 표 글자와 같아졌다. 표시만이다.
   - 서버 값과 견주는 유일한 곳인 `useDropdown` 의 `'전체'` 판정(`useDropdown.tsx:15`, `with-all`/`without-all`)은 `optionLabels` 보다 앞에서 원래 서버 글자로 돈다. 영향 없음.
   - 리렌더와 선택 유지: `optionLabels(...)` 는 렌더마다 새 배열이라 `Dropdown.tsx:114-118` 의 `autoSelectFirst` effect 가 MesTab, OrdersTab 견적 드롭다운과 SearchBar 3곳(기본 `autoSelectFirst=true`)에서 렌더마다 다시 돈다. 하지만 `!value` 일 때만 `onChange` 를 부르고, 첫 선택 뒤에는 value 가 'ALL'(truthy)이라 더 부르지 않는다. 반복 호출이나 루프 없음. 선택 표시는 `items.findIndex(item.key === value)` 라 글자가 바뀌어도 유지된다. `useMemo` 를 안 쓴 것은 맞다(측정 없는 memo 금지, 배열 길이 2~6).
   - 참고: search type 코드(`NUMBER`, `REQUESTER`, `SUPPLIER`, `NAME`)와 생산의 `ALL` 은 목 기준(카드 verified=false). 실서버가 다른 코드를 주면 서버 글자가 그대로 나온다(숨기지는 않음).
2. 로그인 오류(`src/app/(public)/login/page.tsx:105-108`). 문제 없음, 진행자 제안도 없음.
   - 401 → unknownId. 403(same-origin 실패), 400(형식), 404(OIDC 모드에서 데모 로그인 꺼짐), 500 → failed("로그인에 실패했습니다." / "Sign-in failed."). fetch 예외 → network. 응답 모양 이상 → badResponse.
   - "없는 아이디"와 "서버 쪽 실패"는 구분된다. 실제로 없는 아이디는 화면이 먼저 `findDemoAccount` 로 걸러(`page.tsx:91-94`) 요청을 보내지 않는다. 그래서 401 은 거의 안 오고, 오는 실패는 대부분 failed 다. 실패는 빨간 글자로 보이고 숨겨지지 않는다(우선순위 2).
   - 잃은 것: 리버스 프록시가 Host 를 바꿔 same-origin 이 늘 실패하는 배포 오류를 화면 글자로는 더 이상 알 수 없다. 개발자는 네트워크 탭의 403 과 본문으로 본다. 404 는 OIDC 모드에서 `DemoLogin` 이 안 그려지면 생기지 않는 경로다. 보안 면에서 새 구멍은 없다(라우트는 diff 밖, 서버 message 를 덜 보이게 됐을 뿐).
