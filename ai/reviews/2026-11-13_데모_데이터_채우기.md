## 진행자 확인(특히 볼 것 일곱 가지)

1. 번들. 이 카드는 클라이언트 첫 로드 JS 에 목을 끌어들이지 않는다. 화면 코드에서 `src/mocks` 를 import 하는 곳은 두 군데뿐이다. `src/app/providers.tsx:26-28` 은 `NEXT_PUBLIC_API_MOCKING === 'enabled'` 일 때만 `import('@/mocks')` 를 부르는 dynamic import 라 별도 async chunk 이고 HTML 의 첫 `<script src>` 에 안 들어간다(`scripts/measure-bundle.mjs` 는 첫 script 만 센다). `src/server/serverMock.ts` 는 `server-only` 다. 다른 화면 파일의 `mocks/` 는 주석뿐이고(`hrm.endpoints.ts:42`), `seed.ts` 를 import 하는 곳은 `src/mocks/handlers` 와 테스트뿐이다. `.env.local` 에 `NEXT_PUBLIC_API_MOCKING` 이 없어 로컬 운영 빌드는 꺼진 상태로 쟀다. 그런데 이 카드는 화면 코드를 안 바꿨으므로 +0.3~1.6KB 는 이 카드 탓이 아니다. 기준선 커밋 `19791383` 뒤 테스트와 목을 뺀 `src` 22파일이 바뀌었다(`src/lib/queryClient.ts`, `src/lib/api/openapi.gen.ts` 등, 앞 카드들). 원래부터 목이 첫 로드에 있던 것도 아니다. P1 아님, 카드 문장만 틀렸다(M4). 빌드 산출물 grep 은 지시대로 하지 않았다
2. 결정성. 같은 UTC 날짜에는 같은 주문이다(`seedOrders` 날짜별 캐시, `seed.ts:400-406`). 주문 id 는 앞 주가 고정이고 이번 주 안에서는 날짜 정렬(안정 정렬) 뒤에 붙어 날이 바뀌어도 기존 so-NNN 이 안 바뀐다(Codex 도 같은 결론). 단위 테스트는 기대값을 같은 시계로 계산하거나 고정 행(QT-2026-016, SO-2026-001 등)을 써서 날짜에 덜 흔들린다. 시계 고정은 없고 UTC 자정 걸침은 열려 있다(M2). 월 경계와 연말: 번호는 `SO-<주문 연도>-<전체 순번>` 이라 해가 바뀌어도 겹치지 않는다. 재무 월별 손익은 local time 에서 UTC 로 바뀌었고 영업 통계와 같은 창이다. 0건 월요일(M1). 690행 생성은 하루 한 번, 정렬과 고객 집계는 요청마다(M3)
3. 저장소, 404, 상한, 로그인별 상태. 상세 404 는 "현재 쪽"이 아니라 그 로그인의 전체 목록 기준이다(`quotesOf(request).find`, `ordersOf(request).find`, 고객도 같음). 그래서 2쪽 이후 행의 상세는 404 가 아니다. 로그인별 상태는 기존 `salesState`, `purchaseState`, `hrmState` 를 그대로 쓴다. 50건 상한은 그대로 돌고(`state.test.ts` 가 65행에서 위치까지 본다) 주석(`state.ts:48` "목이 페이지를 자르지 않아")만 낡았다(카드 별도 보고 9). 진행자 실행: `state.test.ts`, `src/mocks/state.test.ts` 통과
4. 계약. `paged` 의 `page` 는 기존 `makePage` 를 써서 number, size, totalElements, totalPages, hasNext 다섯 칸이 같다. 화면은 `page`(0 기준, `currentPage - 1`)와 `size` 를 보낸다(직원, BOM, 공급사, 고객, 창고, 견적, 주문, 구매 요청, 발주 아홉 화면 확인). 이 목록 fetcher 를 드롭다운처럼 "전부" 받으려고 부르는 화면은 없다(호출처가 각 표 화면 하나씩). 진행자 실행: `openapi.contract.test.ts` 통과. 쪽 크기 0 이나 숫자 아닌 값은 막지 않지만 화면이 안 보낸다
