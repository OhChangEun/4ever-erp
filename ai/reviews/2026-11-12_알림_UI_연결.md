## 진행자 확인

Codex 답에 항목별 확인 줄이 없어 진행자가 코드로 대조했다. 화면은 띄우지 않았다. 추가로 돌린 테스트: `pnpm exec vitest run` 으로 알림 관련 파일, `src/i18n/messages.test.ts`, `src/test/contract/openapi.contract.test.ts`, `components.i18n.test.tsx` 9파일 119개 통과.

1. 정합성
   1. 목록과 안 읽은 수는 같은 뿌리다. `header.keys.ts:3-9` 에서 `list(page)` 와 `unreadCount()` 가 `['notifications']` 아래다.
   2. 읽음 처리 둘 다 `lists()` 와 `unreadCount()` 를 무효화한다(`notification.mutations.ts:11-12`). 다른 도메인 키는 없다. 무효화는 훅 옵션의 `onSuccess` 에서 돌아(`useInvalidatingMutation.ts:152-156`) 팝오버를 닫아 컴포넌트가 사라져도 실행된다.
   3. 폴링과 SSE 는 겹치지 않는다. SSE 가 붙으면 `refetchInterval` 이 false 다(`NotificationBell.tsx:30`). 뱃지와 목록이 같은 값을 받는다(`NotificationDropdown.tsx:68`).
   4. 낙관적 갱신은 없다. 실패하면 캐시를 안 건드리고 `role=alert` 한 줄만 보인다(`NotificationDropdown.tsx:105-109`).
   5. 읽음 처리는 항목을 지우지 않아 쪽수가 안 변한다. 전체 읽음은 첫 쪽으로 돌린다(`NotificationDropdown.tsx:76`).
   6. 팝오버를 닫으면 목록 쿼리 observer 가 사라지고 키가 쪽 번호별이라 늦게 온 응답이 다른 쪽을 덮지 않는다.
   7. 중복 제출은 공통 빌더의 `inFlight` ref 가 막고(`useInvalidatingMutation.ts:116,182-188`), 진행 중에는 항목이 `aria-disabled` 다.
2. 보안
   1. 인가 규칙 접두사는 `alarm/notifications` 이고 역할은 `ROLES` 전부다(`policy.ts:159-161`). 표에 없는 경로는 원래 로그인만 되면 통과라(`canAccessApi`) 이 규칙이 다른 경로를 넓히지 않는다. 고객사, 공급사 포함 전 역할 테스트가 있다(`policy.test.ts`).
   2. SSE 주소는 `NOTIFICATION_ENDPOINTS.SUBSCRIBE` 그대로고 헤더나 쿼리에 토큰을 안 붙인다(`useNotificationSSE.ts:41-43`). 옛 훅의 `console.info('[SSE] ...', { userId })` 로그는 지워졌다.
   3. `Notification/` 아래에 `dangerouslySetInnerHTML` 0건. 제목과 본문은 글자로만 그린다.
   4. `linkType`, `linkId` 로 이동하는 코드 0건. open redirect 없음.
   5. 서버 목의 저장소는 Authorization 값 전체가 키라 사용자끼리 안 섞인다. 로그인마다 하나씩 늘고 지우는 코드는 없다. 76줄에 `shortcut:` 주석으로 적혀 있다. 브라우저 목은 위 표의 B 1번.
3. 사이드바 QueryClient 가 둘인 것
   1. 알림 키를 쓰는 곳은 `header/` 아래뿐이다(grep `notificationKeys` 결과: keys, mutations, SSE 훅, Bell, Dropdown). 본문 쪽 mutation 이 알림 키를 무효화하는 곳은 없다.
   2. 알림 mutation 과 SSE 훅은 `useQueryClient()` 로 사이드바 쪽 클라이언트를 받는다. 둘 다 사이드바 아래에서 그려진다.
   3. 로그아웃: 데모는 `router.replace('/login')`(`SidebarProfile.tsx:56`)이라 `(private)/layout.tsx` 가 unmount 되고, 다시 로그인하면 `useState` 초기화로 새 클라이언트가 생긴다. OIDC 와 401 은 전체 새로고침이다(`logout.ts:42`, `redirectToLogin.ts:18`). `next.config.ts` 에 `cacheComponents` 가 없어 레이아웃 state 가 숨겨진 채 남는 경로도 없다. 앞 사용자의 알림 캐시가 다음 사용자에게 보일 경로는 못 찾았다. 화면에서 계정을 바꿔 가며 확인하지는 않았다.
   4. `/profile` 은 `Providers` 안에 사이드바가 있어(`(public)/profile/layout.tsx:34-35`) 본문과 같은 클라이언트를 쓴다.
4. FE 품질
   1. `aside` 에 `overflow` 가 없고 알림 버튼은 `nav`(overflow-y-auto)의 형제라 팝오버가 잘리지 않는다(`Sidebar.tsx:50-88`). 접힌 상태(w-16)에서도 `left-full` 기준이 사이드바 오른쪽 끝이다.
   2. 팝오버는 `aside`(z-sidebar 40) 안이라 모달(z-modal 1000) 아래다(`packages/ui/tokens.css:79-83`).
   3. Esc 닫기와 버튼으로 포커스 복귀(`NotificationDropdown.tsx:49-52`), 바깥 누름 닫기(`:55-63`), `aria-haspopup` 과 `aria-expanded`(`NotificationBell.tsx:57-58`)는 있다. `aria-controls` 는 없다. 완료 기준 4는 앞의 둘만 요구한다.
   4. `useQuery` 가 `NotificationBell` 안에 있어 60초 폴링은 `Sidebar` 전체가 아니라 이 컴포넌트만 다시 그린다. `Sidebar.tsx` 의 effect 는 이 diff 에서 안 바뀌었다.
   5. 렌더 중 `setState`(`NotificationBell.tsx:43-46`)는 `unread !== seen` 조건이 한 번 뒤 거짓이 돼 반복되지 않는다.
5. 지운 파일과 메시지 키
   1. `NotificatioApiType`, `NoificationDropdown`, `NotificationPagination`, `header/Header`, `sseError`, `NotificationSseError`, `onAlarm`, `onUnreadCountChange` 를 `src`, `e2e`, `packages/ui/src` 에서 찾았고 0건이다.
   2. `notification` 메시지 키는 ko 20개, en 20개로 같다. 화면이 쓰는 키(`title, readAll, empty, emptyHint, bellLabel, loading, loadFailed, retry, readFailed, newArrived, unread, source.*`)가 전부 있다.
6. 계약
   1. `openapi/everp.yaml` 의 목록 파라미터, 개수 `status`, 읽음 응답 `processedCount`, `linkType` 과 `linkId` 의 null 이 zod(`notification.schemas.ts:14-33`), 목(`alarm.handlers.ts`)과 맞는다. 계약 테스트 통과.
   2. verified=false 표시는 yaml 주석, `notification.schemas.ts:11`, `ARCHITECTURE.md` 10절 332~334줄에 있다.

## 처리 (2026-11-12, erp-dev)

표의 세 건은 처리 칸에 적었다. 표 밖의 것:

1. 진행자 의견 2번(`source` enum): 반영. zod 는 문자열이면 받는다(`notification.schemas.ts:22`). 계약의 응답 `source` 는 enum 을 풀고 설명에 알려진 값을 적었다(요청 파라미터 `source` 는 게이트웨이가 8개만 받아 enum 그대로). 화면은 아는 값만 번역하고 나머지는 메시지 `source.unknown`("알 수 없음", "Unknown")이다. 리뷰의 "기타"는 이 문구를 가리킨 것으로 보고 문구는 바꾸지 않았다. 테스트 3개(목록이 그려지고 그 줄 출처가 "알 수 없음", api 가 모르는 값을 받음, 문자열이 아니면 형식 오류).
2. `aria-controls`: 반영. 열려 있는 동안 알림 버튼이 팝오버 id 를 가리킨다. 틀이 `NotificationBell` 에 있어 청크를 받는 중에도 가리킬 요소가 있다. 테스트 1개와 e2e.
3. 진행자 의견 1번(`Sidebar.tsx:15-26`, 1024px 미만에서 사이드바가 바로 닫힘): 손대지 않음. 카드 "별도 보고"에 적었다.
4. 조정자 결정 4개(portal 없는 팝오버 유지, 시각 형식 유지, `Navigation.tsx` 는 정리 카드에서, 번들 기준선은 조정자가 갱신)는 `../decisions.md` 이 카드 행에 "조정자 확인"으로 적었다.
